# 本周执行方案 v2：MS-HAB 调用／反馈接口基线

本文件取代旧fallback推进顺序。[用户原文](weekly-baseline-v2-user-plan.md)完整保留；不把原文估算当作实测或预算余额。

问题陈述：在固定底层工具和benchmark子任务顺序下，带进度事件的VLM协调能否提高MS-HAB长程任务的完成物体数，其调用与计算代价是多少？本周复现调用/反馈/重规划接口形态，不复现TAPT训练收益。

## 路线与授权边界

- A：LightNav＋官方按物体SAC，另设PPO导航对照。条件1固定调度，条件2GPT＋规则代理，条件3GPT＋独立学习进度。学习头不得未经离线验收接管执行。
- B：用户新授权的一次普通Pick SFT，与旧TAPT训练分开。20示范/100更新吞吐门、总18小时含门和验证的训练墙钟、只训一次、10种子原生门≥3/10才在独立Pick面板替换。旧V8/AC/TAPT训练及数值门不恢复。初始化checkpoint、official state编码/归一化及动作契约须先固定；旧V8 state30不能冒充官方state。
- Runpod仅在B指定低吞吐或lab不可用条件成立时考虑≤6小时；启动前官方插件核账，费用包含临时存储且不超过已有剩余授权。不提前租机、不新增充值承诺。
- 所有GPU工作先串行排队，包括PPO/SAC渲染；CPU物理仍需GPU渲染，不能仅依据显存估计并发训练。LightNav不得和B训练同时占GPU1。
- 发给胡学姐的文字可以起草，实际发送另需明确发送授权。

## 预注册必须补齐的门

[预注册草案](../configs/weekly-baseline-v2.json)固定候选val seeds0–9、7000动作、40请求/$0.05每episode、两导航面板三条件。每个plan UID必须从真实环境绑定并冻结；目前为null，因此禁止据此启动评测。主线40个VLM episode合计技术上限$2，另需从现有API总授权扣除，非新增预算。分支Pick面板预算另登记。

进度头使用独立训练与开发父轨迹：训练scene train seeds100–109，开发train seeds120–124，最终val seeds0–9不进入训练、标注阈值选择或检查点选择。它们是新预注册选择，尚未采集。可以通过条件1的独立训练split收集，但不能训练在条件1最终测试轨迹上再比较条件3。失败尾不标完成；无法从真实证据确定进度的失败帧用mask，不强行线性拉到1。

进度预测需绑定当前调用族和目标指令；相同RGB/qpos在不同调用阶段可能有不同进度，不能默认为一个无条件标量函数足够。先固定g/z条件编码、标签与失败误完成率分母，再开始训练。PPO轨迹分布与LightNav交接不同；LightNav条件3需独立影子验证，不宣称分布自动一致。

作者port阈值数值与来源hash待绑定；规则代理公式也须预先冻结并披露oracle state使用。规则和学习进度事件只触发中断/再决策，不代替原生成功判据。完整任务SR继续报告，完成对象数作为预注册主指标；基础设施失败保留计划N，另报执行N和完成N。不因预期SR低而事后改评分口径。

## A1执行边界

允许navigate/pick/place、同技能retry、40步内reposition、observe、abort。reposition必须有真实导航执行器与可核验安全边界；未实现时拒绝，不能偷偷执行Pick或修改pointer。observe只刷新图像，不用13维零动作冒充静止（夹爪/底盘控制语义不同）。拒绝日志要回到下一决策，并计入请求/墙钟上限，防无限重试。

官方SAC不读语言z，runtime只能记录指令并按已校验目标选择其策略；不能声称自然语言进入SAC网络。它是工具协议占位，导航与VLA后端才可能消费z。固定顺序、oracle目标/状态、恢复动作扩展、独立头和SAC均为与论文的差异；不能写“高层无差异”。历史ignore_arm_checkers=true设置须在新面板冻结前决定并披露，三个条件保持一致。
