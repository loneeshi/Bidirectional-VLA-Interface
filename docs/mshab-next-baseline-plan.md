# MSHAB011 失败分析与下一轮 baseline 计划

依据：MSHAB011 attempt5 的 events.jsonl、模型元数据、GraspMonitor / FetchPiSkill / LightNavSkill 源码与 step330/369/400 工作区观测。分析阶段未新建 GPU 或调用实验 API。

## 已确认与未确认

- 330 步完成第一个导航子任务；76 步操作未出现 is_grasped=true，目标成对接触力记录始终为零。最终因16次协调调用上限结束，末步仿真 terminated/truncated 均为 false。这是未完成任务的预算截断，不能等同原生 fail=true。
- 首次 Pick 40 步中断，后六次各6步中断。闭爪命令连续6步即触发 missed_grasp，不要求夹爪已靠近目标，也不检查实际开度。每次 start 重置监视器计数，形成重复短窗口。
- GPT 指令真实进入操作模型，但改写指令并不证明低层具有重新张爪、对齐的能力。当前仅 Pick/abort 可选，未展示 reach/grasp/move/release 四组 Fetch 适配器或学习进度。
- 37/76 操作步发生限幅；应检查训练/推理归一化和教师动作分布，不能凭限幅断定接口错误。
- 同一操作子任务内 base_xy_origin 未重置；机器人关节顺序、30维状态和13维动作有契约检查，但检查通过不证明语义或数值分布匹配。
- LightNav 每次 bounded call 都 reset 历史，9次调用中有8次40步预算切片。这可能影响导航效率；本轮导航成功，优先级低于 Pick。

## 按验证门推进

1. 本地接口审计：核对训练/推理状态、图像、动作归一化及实际执行动作；给启动流程增加客户端导入、唯一输出目录、真实请求字节数和 bridge 存活预检。监视器记录命令、实际开度、末端/物体位姿及接触；真值只用于诊断，不输入策略。
2. 固定操作起点：保存实际导航结束的完整仿真状态、随机状态、控制器状态和相对坐标原点；验证恢复后观测与状态一致。若无法精确恢复，采用确定性前缀重放并报告残差，不能声称完全同起点。
3. 首轮不训练、无GPT的四格诊断：相同起点下交叉比较训练模板指令/GPT首条指令，以及原6步中断监视器/仅记录事件的监视器。后者仍保留原生终止、碰撞和动作预算限制。每格最多120步，固定随机种子。比较首次接触、首次抓取、实际开度、末端相对目标轨迹和限幅通道。
4. 同起点运行官方SAC作为独立诊断参照，绝不混入纯VLA成绩。SAC成功而π失败指向策略/输入适配；二者都失败则优先排查导航结束姿态和可达性。单起点结果只是定位证据。
5. 根据诊断修复：若监视器提前中断，改为区分接近、闭爪、持物阶段并设置明确恢复窗口；若训练/推理契约错误，先修接口；若固定模板优于GPT指令，补充并验证训练指令覆盖；若同分布仍控制失败，再做小规模Fetch演示适配。避免一次同时改多个因素。
6. π操作门通过后恢复GPT+LightNav+π串行单物体链：导航→抓取→携物导航→放置。协调按完成/失败/停滞及较长的看门狗事件触发，导航历史的保留需与动作队列清空分开；同因连续失败最多两次后有界终止。
7. 独立里程碑：Fetch工具族与学习进度迁移。按轨迹划分训练/验证，分段reach/grasp/move/release，训练工具族LoRA及进度头，验证适配器选择与学习进度实际触发闭环；不能把V8普通LoRA称为TAPT完成。

## 验收、对照与预算

- 工程门：纯VLA完成一次单物体链，有逐请求、动作与反馈证据；示范成功不代表benchmark成绩。
- 初评门：预先固定5个初始状态，同条件比较官方PPO/SAC、固定调度LightNav/π、GPT调度LightNav/π；共享动作预算并另报API/耗时。明确训练重叠。完整五物体任务使用固定官方协议，诊断650步与单物体结果不混入正式成绩。
- 首轮建议单A6000最多60分钟，GPU/临时盘内部上限$0.60，API为0；启动前重新核账及确认剩余授权，超时则归档而非延长。后续训练需依据诊断另定更新数和限额，本计划不自动开启训练。
- 后续完整协调复测拟最多16次GPT调用、$0.32；与GPU费用分别记账，均占用既有总授权。模型加载、部署、备份也计入GPU时长。
- 保留每次失败日志，按录制UTC日期与任务批次建立媒体目录，准确标注结果并更新索引和SHA256。启动前独立停机保护；归档校验后删除临时资源并确认。
