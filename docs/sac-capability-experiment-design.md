# SAC 初始状态能力与有界重试：实验设计

日期：2026-09-21。状态：设计与只读源码核验完成；未修改运行器的终止逻辑，未启动新实验。
本文件是当前实验设计，不是一次性代码提案。信息摘要/image消融暂缓，本周保留evaluator反馈。

## 一、实验要证明什么

假设：如果从官方SAC初始化分布及独立开发数据中识别出的可靠初态范围有用，
那么在MS-HAB TidyHouse中，GPT使用该范围指导物理调整和重试，应比具有相同
调整工具、重试机会和总动作预算但没有能力范围反馈的GPT完成更多对象；
移除能力范围反馈应降低收益。另行检验单纯增加重试机会是否已经解释了收益。

不假设存在一种通用完美姿态。要估计的是给定checkpoint、对象/场景条件和预算下，
从某类状态启动的经验成功率及适用范围。官方生成的初态也不能直接标为成功。

## 二、四根支柱

### 1. Baseline与设置表

| ID | 设置 | 用途 |
|---|---|---|
| H0 | 上周GPT+PPO+逐物体SAC，原生失败截停，16集，13/80对象，0/16整集成功 | 历史参照，不用于新停止规则下的直接改进百分比 |
| C0 | 相同GPT/PPO/SAC，新持续执行协议，常规分段执行，不增加已放弃目标的恢复轮次 | 新协议匹配baseline |
| C1 | C0 + 允许返回失败/已放弃目标进行恢复尝试，额外尝试最多3次 | 测重试收益 |
| C2 | C1 + 冻结SAC初态能力反馈 | 测能力反馈收益，主对照C2对C1 |

C0/C1/C2有完全相同的动作工具与参数能力、图像、历史格式、evaluator字段、模型、
checkpoint、相机、初态、总物理动作上限。C1/C2重试次数一致，只有能力反馈不同。
额外3次是建议的恢复调度规则，不是新增subtask失败截停：它耗尽后调度其他任务，
不会终止整集。普通40步执行切片的继续不计为新的恢复attempt。
首次执行与“明确放弃后重新尝试”的界限必须在事件中标为attempt_started/abandoned/retried。
本表为待冻结设计；实现恢复工具后先用轨迹回放检查这些定义不会把普通继续误算为重试。

### 2. 数据集与划分

- MS-HAB TidyHouse官方逐物体SAC及配套task plans/spawn data。
- 官方train资产用于能力刻画；按父scene/trajectory划分内部拟合与development，
  不把同一初态的帧或重复调用分散到两边。尽可能scene不重叠，无法满足则明确披露。
- 上周16个val plan已被反复分析，继续作为历史配对/开发面板，不再称为未见test。
- 最终测试选择未用于能力建图、门槛或提示词选择的val plan；预先冻结UID，最后统一跑。
- 记录dataset/checkpoint SHA、scene、plan UID、spawn index、所有RNG、对象类别、
  相机配置、depth预处理、动作/控制频率。本文不补造尚未核验的数值。

### 3. 指标

能力实验：原生操作谓词成功、几何操作成功、力违规、首次成功动作数、执行后状态。
几何成功与含力约束的官方成功分开；被提前违规的长轨迹不能凭后来成功恢复官方有效性。

整体实验主指标：episode最后状态实际正确放置并满足稳定条件的唯一对象数（0–5）。
次指标：最终五对象全部完成、ever-completed对象数、曾完成后被破坏数、各subtask
planned/requested/executed/precondition-met/succeeded、恢复成功与全部恢复动作、
GPT逻辑调用/物理请求/token/成本、总动作/墙钟、力峰值/累积值/超限次数。
试过一次不等于完成一次；空夹爪Place不计为合法Place能力评测，但留在覆盖与失败记录里。

报告各随机种子完整面板均值±标准差、逐episode配对差值；独立单位为episode/scene，
不是每个动作或20个相关subtask。planned分母不缩小，基础设施失败/未运行单列。

### 4. 变量控制与消融

- C1对C0：只增加放弃后重新访问目标的机会。
- C2对C1：只增加能力反馈，调整动作工具和预算都相同。
- 同一冻结轨迹上的前缀检查点报告成功-累计动作曲线，避免把更多尝试误当反馈优势。
- 独立初态重复用于估计工具可靠性；在线retry是连续物理状态上的恢复，二者分开。
  同一确定性policy、同一完整状态及RNG的重复执行只算复现检查，不能冒充独立种子。

## 三、系列实验

### E0：核验工具的已知初始化分布

先审计checkpoint配置、官方初始化器及spawn记录，不随机发明站位。
已在实验室官方runtime核验：
- mshab/envs/subtask.py 读取spawn_data_fp，按subtask UID和spawn_selection_idxs取记录。
- 可恢复robot_pos、robot_qpos、obj_raw_pose，以及Place的obj_raw_pose_wrt_tcp。
- Pick/Place的train/val spawn_data.pt在本机资产中存在。
- 实查024_bowl checkpoint：PickSubtaskTrain-v0，train spawn_data，target_randomization=false；
  train max_episode_steps=100，eval_env=200，frame_stack=3。该结论尚不扩展到其他checkpoint。

输出每个checkpoint的适用任务、状态/图像输入、reset分布和资产覆盖表。
随后选已存在且语义匹配的官方spawn作为锚点；每点实际跑SAC验证，保留失败点。
先复现支持分布内的能力，再研究长程PPO交接与这些状态的差异。

### E1：能力范围与交接分布差异

第一小批建议：2个覆盖充分的对象类别 × 3个独立train场景/parent × 2个官方spawn
× Pick/Place各一套 = 最多24个独立短诊断。具体UID冻结在运行前，缺资产就记录缺口，
不按结果挑选类别或场景。Place使用官方持物初始化，明确这是孤立能力诊断。

每个初态记录：base相对目标距离/方位/朝向、torso高度、arm qpos、TCP关系、
物体相对夹爪姿态、支撑面/目标高度、局部障碍、速度、图像与controller状态。
可量化视野遮挡时披露测量来源；缺失字段留null。

对照相同开发目标上由PPO实际导航得到的交接状态：
1. 官方支持分布内也普遍失败：先查checkpoint、预处理、控制/初始化兼容性，不进入GPT先验实验。
2. 支持分布成功而PPO交接失败：检查差异集中于哪些状态维度，再有针对性地做干预验证。
3. 两者都成功：初态可能不是该场景主要瓶颈，不继续无目的扫描。

支持分布距离只能作为候选指标；它不能代替实际成功概率。保存全部成败，给出各区域
成功数/样本数与不确定性，不称少量全成功点为“完美区域”。若使用SAC critic，先核验
权重是否可用及独立校准效果；Q值受奖励/折扣影响，不直接当成功率，本轮不默认依赖critic。

第一批只筛查机制，随后以新的父scene/spawn补足独立验证；不在同一24条数据上既选区域又报泛化。

### E2：在线调整和重试是否进入有效能力范围

实现一个共同的有界物理调整工具，三组接口完全相同。能力反馈给出可执行目标范围、
所依据的样本数与不确定性，而不是要求GPT从世界坐标猜动作。
所有调整、失败和重试继续使用当前环境状态，无reset、teleport、注入抓取或回滚。
重复调用确定性SAC可能继续相同失败，需要检查状态实际改变了什么；状态没变的重复也如实记录。

先在development的2个plan × 3组 = 6集做接口pilot，按每批每组2集保存。
pilot检查停止规则、状态改变、恢复计数和日志；它不用于宣称SR提升。
通过后建议4个development plan × 3个预先固定环境种子 × 3组 = 36集。
最终新val面板规模与资源上限另行冻结；不自动把36集当当前预算授权。

## 四、持续执行协议：仅episode动作上限作为任务超时边界

用户要求：接触力及subtask失败不截停整集，让所有subtask获得执行机会。
建议沿用7000真实动作作为第一版episode总上限，模型checkpoint与动力学不变。
所有恢复动作计入7000。调用仍以最多40动作的窗口向GPT交还控制；这是调度窗口，
不是200/500步subtask失败截停。原生subtask horizon仅记录为诊断事件。

调度采用覆盖队列：所有20个subtask先获得一次有界调用机会，之后按GPT恢复决策分配
剩余动作；所有组使用同一覆盖规则。GPT可以在早期窗口完成目标或让出，后续回来继续。
队列调度不会把未完成目标标成成功。没有抓取时Place保留precondition_unmet标签；
不为了“全部试过”补造持物状态。总预算或物理不可达导致未尝试的项仍明确not_attempted。
这改变了原GPT自由调度及原生顺序执行协议，所以C0必须重跑，H0仅保留参照。

当前官方SequentialTask.evaluate同时更新累积力、倒计时和subtask_pointer：
move_to_next要求subtask_success、力未超限、progressive_task_success全部满足。
因此只忽略runner的fail会导致指针卡死，不能完成本协议。

实现要求：独立实验调度状态与几何任务记分，不修改已冻结官方runtime文件；在新环境
适配层控制步进/终止包装，禁用失败后autoreset，不能反复调用有副作用evaluate。
原生力阈值仍记录；首次官方违规后official_episode_valid=false保持锁存。
执行指针变化标为scheduled/attempted，绝不拿执行指针作为完成数。
最终扫描五个对象实际目标关系，另记完整原生谓词/严格前缀结果与force violations。
力累积保留整集账本及逐调用记录，不通过清零伪装成未超限。

不因force/subtask fail停止仿真；NaN、仿真崩溃或API故障等基础设施异常仍保存并退出。
API/费用/资源授权是外部硬上限，耗尽属于资源截断，不算正常完成，也不自动提高额度。
所有对象已完成且episode目标满足时可自然结束，无需故意消耗剩余动作。
此协议只用于模拟器能力测量，不部署到实体机器人。

## 五、可复现与工程化

- 固定Python/NumPy/框架/CUDA及环境/模型RNG；恢复包含wrapper计数器、frame stack、
  controller target与内部状态、速度、抓取关系。get_state_dict不是默认完整性证明，
  必须验证相同snapshot下首次动作和后续轨迹复现。
- 参数使用配置文件，记录schema/version、commit与dirty/source SHA、依赖/硬件/资产hash。
- 模型保持冻结；保存输入/输出、事件、视频、每次attempt、失败标签及费用ledger。
- 命名 sac-envelope-<split>-<checkpoint>-<parent>-<spawn>-<rng>-<UTC>，
  整体实验 gpt-sac-continuation-<condition>-<plan>-<rng>-<attempt>-<UTC>。
- 使用现有JSONL/manifest/实验表，不引入新的付费追踪服务。小批次2集，退出即保存续跑点。
