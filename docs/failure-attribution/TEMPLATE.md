# 失败归因报告模板

每批实验一份报告，放在 `docs/failure-attribution/YYYY-MM-DD-<批次名>/`。日期用 UTC。范例是 [2026-10-08 C2-r2.5 baseline](2026-10-08-c2-r25-baseline20/report.html)。

## 文件

| 文件 | 内容 |
|---|---|
| `report.html` | 自包含的报告。图片内嵌，不引用外部文件。 |
| `attribution-stats.eval-only.json` | 报告里每个数字的来源。 |

写完后在 [README.md](README.md) 加一行，并在对应的实验日志里加链接和一段摘要。

## 归因步骤

1. 每例取最终尝试。截断例单列，不计入失败。
2. 找出决定性命令。
3. 引用模型自己的 note 和 hindsight，保留原文。
4. 用动作、传感数据和评估侧数据核对模型的说法。模型的说明是自我报告，不能直接当事实。
5. 归入四类之一：模型推理中的错误信念、执行偏离陈述的意图、合理计划被环境击败、无法判定。
6. 给出置信度，并写明依据是数据记录还是看图判断。

## 报告结构

1. **结论**：最多五条，每条一句。
2. **根因分布**：一张分布图，一张“根因 × 终止方式”表。根因和终止方式分开统计。
3. **归因方法**：数据来源、判据门限、图片来源。
4. **每类根因一节**：证据表、机制、代表性原话、图片。
5. **逐例归因**：每例一张可展开的卡片，含过程、决定性命令、原话、核对、系统层助因。
6. **四类归因汇总**，以及系统层助因出现在哪些例。
7. **对下一步的含义**：每项改动能改变哪些例，能不能带来成功。
8. **局限**。

## 必须遵守

- 评估侧真值只用于评分和核对，报告里要写明它没有进入模型请求。
- 第三人称录制帧标注为“仅用于分析”。从图上看出的结论要说明是目视判断。
- 数字都从统计文件取，不手抄。
- 没有验证过的反事实（例如“不碰撞就会成功”）要写进局限。
- 文字用短句，一句一件事。有结构的内容用表格或图。
