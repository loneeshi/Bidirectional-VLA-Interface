# 真实导航交接 SAC Pick 普查：快照复跑门修订提案

**状态：2026-09-25 用户回复“批准”，批准本修订下的前 12 计划续跑；完整批次仍未授权。** 原协议见[运行前设计](real-handoff-pick-baseline-census-experiment-design.md)；接口诊断与原始回执见[首段预检记录](../../research/c2/diagnostics/2026-09-25-real-handoff-pick-preflight.md)。本修订只修改“复跑不一致时是否停止采样、如何报告失败机制”两处；其它冻结条件不变。

## 修订理由和证据

清单第 1 个真实交接，原生 PPO Navigate 在第 78 步完成。自然 SAC Pick 200 步失败，同快照公开状态还原后第 167 步严格成功；直接还原 GPU 缓冲区后第 78 步严格成功；两次都先从 GPU 缓冲区快照还原则分别第 49、151 步严格成功。各次第 0 步 SAC 输入一致、公开状态最大误差 `1.7881393432617188e-7`，接触查询前后状态与输入不变。逐动作、终止步和有时终止状态均不稳定。原协议要求这些量一致并停止，所以目前只有 2／12 计划尝试，不能计算失败构成。

## 拟修订的执行与统计口径

1. **来源与基线不改**：继续使用已冻结、按首个 Navigate UID 字典序选出的 120 计划清单。按顺序尝试，首次有效原生 Navigate→Pick 交接后，只对**自然连续执行的第一次**官方 SAC Pick 计入基线；不从还原状态挑选有利的结局。不改导航、Pick horizon、检查点、分类阈值、接触采样、成功判据、GPU 或 API 配置。已记录的计划 0 导航失败和计划 1 自然 Pick 失败各只算一次，保留其原始回执；接口修复诊断均不算独立样本。
2. **复跑仍做且完整保留**：每例自然基线失败按原协议从交接快照重复一次。记录两次官方终止原因、终止步、自动机制类别、快照还原误差与输入哈希。终止原因／步数／类别不一致者标记为 `unstable_replay`，不删除、不重抽、不替换其自然基线结局，也不把复跑成功计为基线成功。
3. **两个失败机制分母**：主描述表列出自然基线失败的原始机制标签与其未归类数，并同步列出稳定复跑子集的机制计数。两者分别标明分母和 Wilson 区间；不稳定失败不可进入“可重复失败”分母。报告快照结局一致率、机制一致率和步数一致率，以及自动标签与盲审人工标签的一致率。若不稳定或未归类失败超过全部自然失败的三分之一，不用机制多数作后续研究方向判断；仍如实报告基线严格 Pick 成功率。
4. **停止规则变化**：原“出现快照复跑不一致即停止”改为“记录不稳定并继续按清单采集”。接触计量缺失、冻结资产／检查点身份失败、正式评估条件变化、单进程或累计授权超限，仍立即停止。首段完成前 12 计划后，报告有效交接取得率、耗时、自然基线与复跑稳定性；完整批次须另定 GPU1 时间上限并单独授权。
5. **样本与结论边界**：完整批次仍按清单顺序采集 40–60 个有效交接或清单用尽，不因中途结果挑换计划。不做 GPT、底盘调整、候选扫描、Place 或训练。即使取得 40–60 个交接，若机制稳定性差，只能给出原始单次执行的描述性分类，不能推出某机制稳定占多数，更不能推出干预有效。

## 授权边界

批准本提案只允许在原先首段的前 12 个计划、累计 GPU1 3,600 进程秒、单进程 600 秒、API 0 的范围内续跑，且此前所有诊断约 492.84 GPU1 进程秒仍计入累计值。完整 40–60 个交接的 GPU1 上限、实验室货币成本和任何付费资源仍需根据首段吞吐另行确认。未获批准前，继续维持原设计停止门。
