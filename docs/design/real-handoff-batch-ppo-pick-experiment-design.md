## 问题与样本

问题：在首次自然 Pick 失败的真实 PPO→SAC 交接上，GPT 提出的一批连续站位，有多少能通过路线和抓取检查、被 PPO 真实到达，并使官方 SAC 严格 Pick 成功？

固定样本为普查的 20 个自然失败位置：1、9、12、14、19、20、23、25、26、31、34、37、39、42、51、55、57、58、59、61。清单由只读脚本 `scripts/freeze_real_handoff_batch_navigation.py` 从原始普查结果和冻结 roster 生成，包含每例的 UID、快照和结果哈希；结果标签不送给 GPT。14 例符合原可重复失败标准，6 例不符合。首次运行的 `0/20` 是**按失败结果选样的事实**；原无动作复跑中已有 4/20 成功，因此另跑同批无动作对照，不把任何候选成功直接归因为干预。

本批只研究这些已选失败，不估计全部交接的净收益和对原成功案例的误伤；这两项要在独立全交接验收集测量。

## 冻结的决策与执行协议

1. 从每个交接的同一冻结快照恢复 Pick 第 0 步，核对 UID、快照 SHA-256、物理状态误差 ≤1e-5、SAC 输入哈希、任务指针及剩余步数。另开一条无动作 SAC 对照分支。本批只测第 0 步选位；第 10 步及后续动态再选位是另一项协议，不混入本批。
2. 从当前物理状态生成三张输入：头部相机、手部相机和带目标标记的物理碰撞网格俯视图。地图使用仿真特权信息；图像只供 GPT 判断布局，硬性检查在连续几何上进行。禁止提供普查失败类型、历史候选结果、同例控制结局或其它 Oracle 成败标签。
3. GPT 每批按抓取适合度排序提出 5–8 个世界坐标底盘位姿 `(x_m, y_m, yaw_rad)`，不限定旧候选 ID；输入显式给目标世界 XY 与 `atan2(目标 Y－候选 Y, 目标 X－候选 X)` 朝向计算。目标离当前底盘 ≤3 m。所有提出的点依序执行地面与全身路线检查、终点 IK 和抓取避碰；记录每点的接受或拒绝原因。IK 先尝试官方抓取资产的完整末端姿态和静态关节路径；找不到时，再以资产中 TCP 位置做自由腕部朝向的有界 IK，并要求终点无新增碰撞。后者只证明末端位置可达且终点无碰撞，不证明抓取朝向、机械臂沿途轨迹或 SAC 成功。现有路线器只搜索直接路线和少数侧向折线，未找到路径不等于全场景无路径。若通过不足 3 个，将全部检查结果转换成可读反馈，最多再请求 1 批。最多 2 批、每批 8 点、每例 2 次模型请求；最后按 GPT 排序冻结最多 3 个**不同的可执行站位**。不足 3 个如实记录。
4. 候选依次试验，首个严格成功后停止。**每个候选从同一交接快照独立恢复**；前一个因碰撞或官方力限终止，不会剥夺下一个候选的试验机会。每条分支先重新执行路线／IK 检查，再调用 Pick 阶段实验性 PPO 路标导航；逐动作检查实际路线、力、碰撞及 Pick 时钟。PPO 动作前补偿一个 Pick 技能时钟单位，使动作后剩余 Pick 步数不变；物理状态、累计力和全局环境动作数照常推进。到位后复查 IK，再继续官方逐物体 SAC 至原生终局。若 30 个连续动作没有使平面距离加 0.2 倍朝向误差至少改善 0.01 m，记 `navigation_stalled` 并从实测状态续跑 SAC。若出现新碰撞、超力或到位 IK 失败，立即停止该分支并试下一个候选，记录为安全门失败。一般未到位但未触发安全门时，从实测状态续跑 SAC，单列未到位。成功判据仍检查官方 Pick 完成、未失败且累计力低于力限；因导航额外获得物理动作，这不是原生官方时钟下的 benchmark 严格 Pick 成绩。
5. 每条候选独立报告：GPT 排名、位姿、路线/IK 接受、PPO 到位、移动动作数、终止原因、暂停时钟协议下的 Pick 成功、累计力与 PPO/SAC 动作数。主描述量为 20 例中至少一个候选成功的数目，同时并列新无动作对照成功数及原来的 4/20 复跑成功数。不能把三次独立分支称为一次连续 episode 内的三次恢复，也不能把暂停时钟干预与原生对照的差异解释为纯 GPT 选位效果。

## 可复核轨迹

每例保留 GPT 的完整 system prompt、结构化 payload、三张输入图及 SHA-256、原始 provider 文本、request ID、token 回执、两批候选和逐点检查反馈。每候选另存独立分支的恢复校验、每个 PPO/SAC 动作、实测底盘位姿、目标距离、接触力、累计力、时钟、原生终止与评分。输出放在忽略 Git 的 `runs/real-handoff-pick-batch-navigation-20260927/`，公开日志只链接摘要和哈希，不上传原始相机或付费请求全文。

## 执行前验收门

- 先用 CPU 合成端口测试：整批拒绝后的可读反馈、批次限制、相同位姿去重、第一候选原生碰撞终止后第二候选仍独立恢复、未到位仍取得官方终局、GPT 请求/回复/图像落盘。
- 在实验室 GPU1 上先做位置 25（早期底盘碰撞）和 37（够不到）的接口预检，确认地图覆盖、几何导出、IK 检查器、PPO 合成路标观测、实际到位与逐步日志。两例均无通过路线与 IK 的站位，PPO 未被调用。随后增加冻结失败集中的位置 1 作单独正例接口检查：该例自然 SAC 曾抓住物体但未严格完成，用于判断有限 IK 搜索是否能找到见证，以及可行站位是否能触发真实 PPO；其结果仍按原 20 例清单报告。不能以静态地图或单元测试代替真实到位。
- 预检授权见 `real-handoff-batch-ppo-preflight-authorization-proposal.json`：GPU1 合计 ≤1,800 进程秒、每例 ≤900 秒；`gpt-5.6-luna` 每例 ≤2 请求、两例合计 ≤4 请求、USD 预留 ≤1.00；实验室项目收费 0；零重试。用户在 2026-09-27 明确批准完成实验所需授权。预检只覆盖位置 25、37；其余 18 例在预检后另冻结范围和额度。
- 停止条件：快照或输入哈希不符；碰撞形状缺失；IK 检查器无效；PPO 动作/观测契约不符；任一分支时钟或累计力被重置；模型请求或 GPU 达到授权上限。接口错误单列删失，不计严格失败。
- 正式 20 例需在预检完成后冻结代码、模型、提示词、阈值、检查点和费用上限，并另行取得批次授权。GPU0、RunPod、新训练不在方案内。
