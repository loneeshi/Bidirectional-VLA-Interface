### 2026-09-26 第二步结果触发的执行分支

研究问题是：在新的真实交接上，GPT 判断何时执行 `forward_10`，相对无干预及开发集冻结的规则门控，能否提高**全部有效交接**的严格 Pick 成功率？`forward_10` 是从第二步失败起点事后选出的动作，选择过程属于开发集；验收集必须另取，不能把 5/14 或 4/5 当作该门控方法的净收益。

| 主臂 | Pick 第 0 步的决策 | 执行动作 |
|---|---|---|
| G0 | 不干预 | 无 |
| G0′ | 不干预独立复跑 | 无；估计同快照随机差异 |
| G1 | 对每个交接无条件干预 | `forward_10` |
| G2 | 开发集冻结的确定性规则决定是否干预 | 干预时 `forward_10` |
| G3 | GPT 输出 `p_fail` 与 `intervene` 布尔值；直接采用其门控决策 | 干预时 `forward_10` |
| G4（次级） | 对同一 GPT 请求的 `p_fail` 应用开发集冻结阈值 | 干预时 `forward_10` |

G2/G3/G4 不干预时复用 G0 的结局。每个交接的 GPT 最多调用一次，G3/G4 共用该响应；任何格式或调用失败按“不干预”处理并计入分母，不重试。动作必须经同第二步的静态路线预检和动态到位检查。静态路线拒绝时没有动作，可复用 G0；动作已开始但未到位时从实际状态继续 SAC，按实际终局计入该组，同时单列未到位。不能把路线拒绝或未到位本身改写为严格 Pick 失败或救回。主比较为 G3 对 G2、G3 对 G0，次级为 G4 对 G2、G1 对 G0。主指标仍是全部有效交接上的救回减误伤，并与 G0/G0′ 随机不一致数并列报告。

## 原始条件性草案（历史记录，A 组不作为本次执行协议）

本实验是 C2 三步中的第三步，问的是：**在 SAC 开始前让 GPT 检查交接站位，只在它判断会失败时才调整底盘，能否在全部真实交接上带来净提升？** 关键约束有三条：

- **必须胜过不用 GPT 的对照**：固定动作、规则门控、几何启发式都要一起比；
- **净收益以全部交接为分母**，救回和误伤都算；
- **在未见过的新交接上验收**，第一、二步的 60 个交接只能用作开发集。

之所以把 GPT 放在 Pick 开始前，而不是执行中：普查中可重复的底盘碰撞多在 Pick 第 12–14 步就因累计力超限终止，执行中第 10／20 步的检查来不及；#011 也显示对原本会成功的轨迹做中途调整会造成误伤。

### 对照组（每个交接配对，同一快照独立还原）

| 组 | 何时干预 | 选哪个动作 | 作用 |
|---|---|---|---|
| **A0 无干预** | 从不 | — | 基线 |

### 判读（写在运行前）

- **GPT 有价值**：A4（或 A5）净收益为正且检验显著，并且相对 A3 的配对差也为正。只胜过 A0、不胜过 A3，只能说"Pick 前干预有用"，不能归功于 GPT。
- **GPT 不劣于启发式**：只胜过 A0、与 A3 打平，结论是"GPT 可作为不需手写规则的替代方案"，不宣称优势。
- **无净收益**：A4 的救回被误伤抵消，或干预召回很低（大部分失败 GPT 都选了继续），分别报告原因。后者说明需要改进判断信号或采用 A5 的决策分离。
- **验收集不足 80 个交接，或 A0/A0′ 不一致数过大**：只报告探索性结果。

### 运行门与停止规则

1. **启动前提**：第二步达到"有提升空间"档，并且其判读已经写入日志。
2. **开发集阶段（需授权）**：在普查的 60 个交接上冻结门控阈值、单一最佳固定动作、启发式规则与提示词。GPT 在开发集上只用来验证接口与输出格式，结果可以看，但冻结后不再改。
3. **验收集阶段（需另行授权）**：冻结清单后按位置顺序执行，各组全部运行后统一评分，中途不看组间比较，不提前停止。
4. 资产身份不符、接触计量缺失、评估条件改变、GPU 或 API 上限超限时，立即停止。
