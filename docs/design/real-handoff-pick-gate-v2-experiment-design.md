# 真实导航交接 Pick 第 0 步干预收益门控：V2 修订设计

**状态：V2 开发批已完成并在预注册区分力门停止；新交接验收未启动。结果见[实验日志](../log/2026-09-26-c2-real-handoff-pick-gate-v2-development.md)。** [V1 开发结果](../../research/c2/diagnostics/2026-09-26-real-handoff-pick-gate-development.md)显示原生 GPT `intervene` 为 60/60，全干预，无法检验“何时干预”。用户选择先修订设计。本版本保留唯一动作 `forward_10` 与官方严格 Pick 评分，把模型预测对象改为**前移相对原站位的成功概率差**；不把原站位失败风险当作动作收益。

## 要检验的量

对于同一真实 PPO Navigate→SAC Pick 交接，令 `Y_hold` 为直接继续官方 SAC 的严格 Pick 成功（0/1），`Y_forward` 为先尝试前移 0.10 m、再在同一 Pick episode 继续 SAC 的严格 Pick 成功。模型从交接时的双相机图像和来源标明的几何输入预测 `p_strict_if_hold`、`p_strict_if_forward`，定义 `d = p_strict_if_forward - p_strict_if_hold`。模型没有得到该交接任何终局或动作标签。

主科学问题仍是新交接全部有效分母上的 `G3` 相对 `G2` 和 `G0` 的**救回减误伤**；`G4` 是开发集调阈的次级门控。路线合法、实际到位、同 episode 步数与累计力连续、官方严格 Pick 终局是执行与计量门，不能代替主科学问题。单次 `Y_forward - Y_hold` 受仿真随机性影响，必须和无动作独立复跑的 `Y_hold′` 不一致数一起解读。

## 冻结样本与干预

- **开发集**：V1 使用的原普查 60 个有效交接，固定清单位置 0–63、UID 与快照身份不变。首批接口预检严格按其中前两个有效位置 1、3；通过后按其余位置顺序完成。不能挑困难案例。普查首次严格 Pick 标签可用于开发阈值，但不得送入模型。
- **验收集**：沿已冻结的[176 个候选 UID](../../research/c2/diagnostics/2026-09-26-real-handoff-pick-gate-holdout.json)（位置 64–239，SHA-256 `39e43f4a6f66bed9961f91f0f17547b00c97b4ed0841d4b87becfb4d27497181`）依序收集 120 个有效真实交接；清单耗尽后至少 80 个有效者仅作探索性结果。任何验收终局在 V2 提示词、阈值、代码、模型和输入哈希冻结前不可查看。开发和验收 UID 不重叠。
- **动作**：`forward_10` 是第二步独立失败起点扫描得出的固定动作，不在 V2 中重新选动作。G1/G2/G3/G4 选中时先做静态路线检查：拒绝则无动作并复用 G0；动作一旦开始，即使未到位也从实际状态继续官方 SAC 并按严格 Pick 终局计分，另列未到位。动作消耗同一 Pick 时钟和累计力。不得直接改 pose、重置预算或把未到位直接记失败。

## 对照臂与门控

| 臂 | 决策 | 评分来源 |
| --- | --- | --- |
| G0 | 无干预 | 新交接直接 SAC；开发集已有普查首次结果 |
| G0′ | 无干预独立复跑 | 同快照与 G0 的随机不一致包络 |
| G1 | 无条件尝试 `forward_10` | 动作后实际官方 Pick 终局；路线拒绝复用 G0 |
| G2 | 原开发集冻结规则 `target_height_m < 0.73271596431732178` | 选中取 G1，否则 G0；规则不重调 |
| G3（主门控） | `d > 0` | 选中取 G1，否则 G0 |
| G4（次级） | `d > t_dev` | 阈值只从 V2 开发集 G0/G1 的配对终局选出；选中取 G1，否则 G0 |

G3/G4 共用每个交接的一次 GPT 响应；格式错误、超时、身份变化或调用错误按“不干预”进入意向分析，保留请求/费用回执，不重试。G3 使用严格正差，`d=0` 时不干预，避免再把一个无限制布尔输出当成行为门。模型预测的两种概率与真实配对终局分别报告；它们只是预测，不是反事实真值。

## 模型输入与防泄漏

V2 复用 V1 的 60 份开发集同帧图像和第 0 步数字段，manifest SHA-256 `617a6390764cdf662f7c398ff5cd8e509a6c5cbefe11364f9ff6fbe138a2da17`。每次包含头/腕两张 128×128 PNG，`detail=low`；几何值注明 `privileged_simulator_at_handoff`，不能称纯视觉。不得包含普查或 G1/G0′ 结果、失败机制、前次模型输出、计划 UID、Oracle 标签、其他交接经验或验收结局。若某交接输入缺失，但身份和官方 Pick 仍有效，G3/G4 不干预并留在分母；身份或官方计量不可核证才列接口删失。

[V2 提示词提案](../../research/c2/docs/real-handoff-pick-gate-v2-prompt-proposal.txt)和[模型配置提案](../../research/c2/docs/real-handoff-pick-gate-v2-model-config-proposal.json)已写出：`gpt-5.6-luna`、low reasoning、Responses 严格 JSON、两概率加简短理由、最多 1,024 输出 token、30 秒超时、零重试。两项预测都针对**官方严格 Pick**；前移预测包含路线拒绝回退、未到位从实际状态继续、步数与累计力代价。执行授权前需计算并固定提示词、配置、输入 manifest、模型返回身份与所有运行器哈希。不能根据 V2 开发标签再改提示词；若修改，另起版本和预算。

## 开发运行、阈值和停止门

1. CPU 审计 V2 请求哈希、字段、图像同帧绑定及无结局泄漏；GPU1 只读核验空闲、存储、权限、调度规则。先用位置 1、3 验证 G0′/G1 快照恢复、静态路线与动态未到位继续 SAC、官方严格终局和同 episode 计量。任一身份、力、时钟或 checkpoint 门失败即停止，修复后在原授权内保留失败回执；不得把失败当作动作结果。
2. 按冻结顺序对开发集 60 例各做 G0′ 和 G1 独立复跑，包含前述预检两例，目标 120 个条件进程。每例的路线拒绝、未到位、严格成功及动作步数均单列。原普查 G0 与新 G0′ 不一致数估计噪声；仅 `G1` 的官方终局能给出动作后的救回/误伤，不能由 GPT 选择标签代替。
3. 运行器和资产核证后，对 60 份开发输入各发一次 V2 请求，先单例验证响应，再完成剩余请求。模型不能读取第 2 步的结果文件。冻结 G4 的 `t_dev`：在开发集所有不同 `d` 的相邻中点及 `-1,0,1` 上，最大化 `Σ(Y_G4−Y_G0)`；并列依次选**更少干预**、更高阈值。报告该选择的开发集乐观偏差，绝不称为确认性效果。失败响应的 G3/G4 均按不干预。
4. **进入验收前的区分力门**：60 个开发样本与 120 条条件回执完整；G0/G0′ 不一致数 ≤12/60；G1 对 G0 至少 4 次救回和 4 次误伤；G3 干预数 10–50/60，且与 G2 至少 10 个决策不同。若任一门失败，报告失败的可区分性并停止 V2 验收申请；不重调同版提示词追过门。G4 无论阈值结果如何都作为次级描述，不用它替代未过门的 G3。
5. 验收批需要**另一份授权**和独立账本。通过开发门后冻结 G4 阈值、模型与代码身份，才对新交接顺序运行 G0/G0′/G1 与一次 GPT 请求。所有组完成后统一评分；主要报告 G3 对 G2、G3 对 G0 的严格 Pick 救回、误伤、净数和配对区间，同时列出 G0/G0′ 不一致；G4 对 G2、G1 对 G0 为次级。不得中途看组间结果再改样本或阈值。
