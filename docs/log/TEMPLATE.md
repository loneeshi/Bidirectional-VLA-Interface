# 实验日志模板

适用于后续所有新日志；与 Weekly 使用相同的实验名称和结果口径。语言简洁，先解释问题，再列设置和结果。

## 写作要求

- 每个实验依次写：要回答的问题、设置、结果、结论、局限、链接；问题用一句大白话，结论和局限各最多两句。
- Q1–Q5 等题目用 `-` 列点，一题一句，写清模型要判断什么、用什么证据评分；不把题目说明塞进结果表。
- 不同 setting 必须用表格对比，包含模型输入、提示、输出或动作、真值使用情况。P0/P1、模型简称、动作 ID 等第一次出现时解释；共有配置放表外。
- 设置交代样本来源、数量、开发或测试划分、谁决策、是否真实移动、成功判据、时限或动作数，以及模型版本、推理档位、调用数和重试。
- 结果必须有表格；一行一个条件或样本、一列一个指标、一格一个数，每张表最多六列。指标过多时分表，不在一个格子里并列多个分数或塞解释段落。
- 表头注明分母或单位，例如“Q2 答对（11 动作）”“严格 Pick（20 交接）”“距离误差（m）”；表下解释必要口径。
- `a/b` 要说明是答对数、检查通过数还是实际任务成功数。SR 只用于实际执行的任务成功率；离线准确率、路线通过率、IK 见证和接口有效率分别命名。
- `✓/✗` 表示该列判据通过/未通过，`—` 表示不适用或未测。未执行的任务不写成 0% 成功；有界搜索没有见证不写成全局无解。
- 特权真值输入单独标注；没有正例或样本太少时在局限中说明。分母按独立起点和回答次数区分，多个模型或提示的回答不是新增场景。
- 没有可报告数据时写“无结果，原因：……”，不造表。费用估算、授权上限和实账分开，实账未知时明确写待核。
- 数字必须能对应原始日志、诊断或评分报告；保留相对链接和代码/run 标识，不复制大段事件流。一次实验可以有多张指标表，不跨实验重复汇总。

# YYYY-MM-DD · 实验名

日期按 UTC；需要时注明本地日期。当前主线阶段、本次推进、阻塞和下一验收门各用短语说明。

**要回答的问题**：一句话说明想验证什么。

**设置**

- 样本：来源、数量、划分与重复次数。
- 共用配置：模型及推理档位、时限、调用数与重试、执行方式、评分依据。

| 设置 | 输入 | 提示或决策方式 | 输出或执行方式 | 真值使用 |
|---|---|---|---|---|
| 条件 A | 写具体输入 | 解释提示代号 | 写清动作或答案 | 主输入/评分端/特权消融 |
| 条件 B | 写相对 A 的变化 | 解释提示代号 | 写清动作或答案 | 主输入/评分端/特权消融 |

若有多道题，按以下形式写；没有则省略：

- Q1：问题内容；评分依据。
- Q2：问题内容；评分依据。
- Q3：问题内容；评分依据。
- Q4：问题内容；评分依据。
- Q5：问题内容；评分依据。

**结果**

说明下面的分数属于答题、静态检查还是实际任务执行。

| 设置 | 指标一（N 例） | 指标二（单位） |
|---|---:|---:|
| 条件 A | a/N | 数值 |
| 条件 B | b/N | 数值 |

必要口径放在表下，最多一行；按需增加其它指标表，每表最多六列。

**结论**：最多两句，说明这次回答了什么。

**局限**：最多两句，说明样本、评分或执行上的边界。

**链接**：[设计](相对路径) · [原始结果或诊断](相对路径)

记录信息：run ID、代码版本；费用以财务子账为准。
