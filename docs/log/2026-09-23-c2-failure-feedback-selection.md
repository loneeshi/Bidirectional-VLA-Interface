# C2 结构化失败反馈与 Pick 站位选择（2026-09-23 UTC）

本批问：同一个 C0 Pick 失败后，只增加一张从真实 C0 记录确定性生成的失败卡片，GPT 会不会改选新站位，并因此选中更多官方严格 Pick 成功候选？这是同一场景三个状态的探索性**离线选择**，不是失败后的在线恢复或完整任务成功率。候选 SAC 结果来自各自独立重建的原交接状态。[设计](../../research/c2/docs/failure-feedback-selection-experiment-design.md)、[A1–A3 原记录](2026-09-23-c2-sac-pose-capability.md)和[机器摘要](../results/c2-failure-feedback-selection-2026-09-23/summary.json)给出边界与数字。

失败卡片的 `sac_steps`、最终累计力和结束时抓持状态来自对应 C0 官方记录；终止原因由累计力判定和剩余官方步数计算，力阈值为 5000。三组卡片分别是：seed8 为 27 步、累计力 5558.282、力超限、未抓住；seed4 为 39 步、累计力 1126.852、剩余时限耗尽、未抓住；seed9 为 26 步、累计力 10732.163、力超限、未抓住。原始 C0 来源哈希逐字段列在冻结清单中。

### 结果

| 状态 | 候选严格成功 | 事后 Oracle | B0 所选 / 严格 Pick | B1 所选 / 严格 Pick | B1 相对 B0 |
|---|---:|---|---|---|---|
| seed8 | 0/4 | 失败 | C5 / 失败 | C5 / 失败 | 持平，未改选 |
| seed4 | 0/4 | 失败 | C4 / 失败 | C4 / 失败 | 持平，未改选 |
| seed9 | 5/6 | 成功 | C1 / 成功 | C1 / 成功 | 持平，未改选 |

B0 和 B1 各为 **1/3** 所选候选严格 Pick 成功，协议有效率 **6/6**。六次外部请求共返回 **5002 输入、338 输出 token**。

### 判别力审计

这批数据对“失败卡片能否提高选择成功数”**几乎没有判别力**。seed8 和 seed4 的候选全失败，任何合法选择都得到同一评分；唯一能区分选择好坏的 seed9 又有 5/6 候选成功，选中成功项本身并不难。B0/B1 在三个状态都选了相同 ID，因此可确认的局部事实仅是：这张卡片在这三份冻结输入上没有改变这一次模型输出。`1/3` 主要反映各状态是否存在成功候选，不能当作有意义的选择准确率比较。

单状态、每组各一次回答无法估计模型输出波动，也无法判断换一种失败描述、另一类失败状态或其他场景会怎样。本批结果既不支持改善，也不能作为“结构化失败反馈无效”的证据。它保留为输入隔离和调用协议的实测记录；方法效果需要新的、结果有区分度的独立状态再检验。
