## 实验 #002：A2 固定新站位 SAC 扫描

- **日期**：2026-09-23 UTC
- **要回答的问题**：在同一交接中，每次只改底盘一个量，官方严格 Pick 结果会不会改变？
- **run 名称 / ID**：`a2-seed19-*`、`a2-seed8-*`、`a2-seed4-*`、`a2-seed9-*`；原始 A2 摘要 SHA256 `9434542e0f31a8ea2add95da7a65a439ee86e044f29371362c652f3bb2209ef0`
- **代码版本**：原批 runner SHA256 `0f28a09a8cbe042459cf68dd6a86f1d6b09b59f32f96e24c77b1493393dc7d`；seed9 配对检查版 SHA256 `d4682db0d0855adb1402f060b49a8540983942dbb0d3597d8b51bf217d5fd5cb`；官方运行时同实验 #001
- **环境**：同实验 #001；实验室 GPU1

### 配置（评测参数）

| 项 | 值 |
|---|---|
| 任务 & 数据划分 | A1 可重复的四个 Pick 交接；每个候选独立从同一初态和历史动作重建 |
| 导航策略 | 不调用导航；直接编辑仿真中的底盘起始位姿，随后执行共同的一帧全零稳定动作 |
| Pick / Place 策略 | 与 C0 相同的官方逐物体 SAC；只测试 Pick |
| 调度器 / 通讯协议 | 无 GPT、无随机抽签；C1/C2 局部前/后各 0.20 m，C3/C4 局部左/右各 0.20 m，C5/C6 偏航 ±0.35 rad |
| observation / policy state | 除指定的一个底盘量外，保持 checkpoint、控制器、RNG、机器人其它关节、物体和任务计数 |
| skill horizon / episode 上限 | 每个有效新候选最多 200 步，保留官方剩余 Pick 时限 |
| 模型调用与费用边界 | 付费模型 API 0；A1–A2 授权 GPU1 累计上限 5400 秒 |
| 其它关键设置 | 稳定后明显漂移或任务失效者标为干预不可行，不调用 SAC；Oracle 在事后读取 C0 和有效候选的最好结果 |

### 结果

| 状态 | C0 | 新候选逐项严格 Pick | 候选平均 | Oracle |
|---|---|---|---:|---|
| seed19 | 成功 | C1 失败；C2 失败；**C4 成功**；C5 失败；C6 失败；C3 干预不可行 | 1/5 | 成功 |
| seed8 | 失败 | C2/C4/C5/C6 全失败；C1/C3 干预不可行 | 0/4 | 失败 |
| seed4 | 失败 | C2/C4/C5/C6 全失败；C1/C3 干预不可行 | 0/4 | 失败 |
| seed9 | 失败 | **C1/C2/C3/C5/C6 成功**；C4 失败 | 5/6 | 成功 |

共执行 **19 次新候选 SAC，其中 6 次严格 Pick 成功**。Oracle 在四个状态中成功 **2/4**，原站位 C0 成功 **1/4**。候选平均是各状态已执行新候选的成功比例，不是另做随机实验；Oracle 知道事后答案，不是可部署策略。

A1–A2 实际累计使用实验室 GPU1 **4008.9052/5400 秒**，剩余授权 **1391.0948 秒**；没有付费模型调用或新租 RunPod 计算。实验室实际费用尚未核对。

### 观察与结论

- **观察**：seed19 出现成功→成功和成功→失败；seed9 出现失败→成功。因此，SAC 的严格 Pick 结果在这两个冻结状态对初始站位敏感。
- **失败原因**：seed19 的四个失败新候选和 seed8 的四个失败新候选均因累计力超限；seed4 的四个候选均在官方剩余第 39 步时限耗尽且力仍合规；seed9 C4 因累计力超限失败。
- **异常**：seed9 的原绝对 XY 漂移门槛曾在 SAC 前挡住六个候选；同处理 C0 也漂移 0.040919 m。观察任何 seed9 候选 SAC 结果前，改用“候选稳定落点相对 C0 稳定落点加预设位移”的配对残差检查，六个候选均通过；原停止记录保留。seed8 C2 曾因源码哈希错误在仿真前退出，匹配运行时重跑后才计入结果。
- **结论**：在这四个交接中确实测到站位影响，且 seed9 有一次状态的失败→成功证据。有限抓取逆运动学检查曾对 seed19 C4 找不到见证，但该候选实测严格成功，不能把“无见证”当作 SAC 必败。这些数字不能换算成完整任务成功率或跨场景表现。

## 实验 #003：A3 GPT 候选选择（探索性）

- **日期**：2026-09-23 UTC
- **要回答的问题**：只看 SAC 前信息的 GPT，在这四个状态上能否选得比候选平均更好？
- **run 名称 / ID**：`a3-choice-exploratory-20260923`；评分文件 SHA256 `4cd540ab7fbd0db2cc65abd181db48bcb6db2c2a58651f04e443e10ec280d69e`
- **代码版本**：图像导出 runner SHA256 `dcd3bc3371b5f5797628ef160ba01c8f8b94c0c3f5415aabdf66f6ec7e3172ad`；输入编译/调用源码 SHA256 `c40885bc922433de657e5dd78a3db9aafec9520eddd5fa7fa7e77d0466363492`
- **环境**：实验室 GPU1 导出图像；本地向 OpenAI API 发起四次请求；本阶段不运行新 SAC

### 配置（评测参数）

| 项 | 值 |
|---|---|
| 任务 & 数据划分 | A1 可重复的四个状态，沿用 A2 全部有效新候选；不筛掉失败状态 |
| 导航策略 | 无；候选图像来自仿真中直接设置该起始站位并稳定一帧之后、SAC 之前，不是实际导航到达图像 |
| Pick / Place 策略 | 不新增 SAC；从 A2 结果表读取模型所选候选的严格 Pick 结果 |
| 调度器 / 通讯协议 | 每状态一次 `gpt-5.6-luna` 请求，只能输出一个有效 `candidate_id` |
| observation / policy state | 当前 C0 与所有有效新候选各自的头部/手部相机图像拼图，加当前状态和相对位移；不提供 A2 成败标签 |
| skill horizon / episode 上限 | 不运行完整 episode；每状态一次选择，零重试 |
| 模型调用与费用边界 | `reasoning_effort=none`、图像 `high`、最多 2048 输出 token；4 请求、USD 0.10 预留上限、GPU1 图像导出上限 900 秒 |
| 其它关键设置 | 完整真实输入在看到 A2 结果后才冻结，因此按用户授权标为探索性，不能补称事前冻结的确认性检验 |

### 结果

| 状态 | C0 | 有效候选成功数 | GPT 所选 | 所选严格 Pick | Oracle |
|---|---|---:|---|---|---|
| seed19 | 成功 | 1/5 | C1 | 失败 | 成功 |
| seed8 | 失败 | 0/4 | C5 | 失败 | 失败 |
| seed4 | 失败 | 0/4 | C4 | 失败 | 失败 |
| seed9 | 失败 | 5/6 | C4 | 失败 | 成功 |

四次输出都符合候选协议。GPT **0/4**；四个状态的候选成功比例平均 **25.83%**；Oracle **2/4**；C0 **1/4**。23 次图像导出使用 GPU1 **804.1002/900 秒**；四次 API 请求合计 **4682 输入、195 输出 token**。USD 0.10 是预留上限，不是实际账单；供应商实际费用和实验室 GPU 单价仍未核对。

### 观察与结论

- **观察**：两个存在成功新候选的状态（seed19、seed9），GPT 都选中失败项；seed9 六个候选中只有 C4 失败，GPT 恰好选择 C4。
- **异常**：本阶段只导出调用前图像并做离线选择，没有让 GPT 控制机器人移动或重新运行 SAC；输入虽然不含 A2 标签，仍是在 A2 结果出现后编译和冻结。
- **结论**：本批探索性 GPT 选择没有超过候选平均。四个同场景状态不足以判断 GPT 的一般站位选择能力，也不能将此结果报告为整集任务成功率。
