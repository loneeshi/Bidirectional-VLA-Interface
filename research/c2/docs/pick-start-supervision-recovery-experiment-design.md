# Pick 子任务起始监督与失败救回：实验设计

本记录沿用 [`docs/log/TEMPLATE.md`](../../../docs/log/TEMPLATE.md)。胡博士截图提出近距起点与中途干预的研究方向；本协议以用户明确要求的“Pick 子任务一开始调用 GPT、之后再检查、寻找失败→成功的真实轨迹”为准。上一批 [近距实验](near-visible-pick-intervention-experiment-design.md) 的 `run-v3`、触发器、结果与账本保持原样，不以本协议改写旧结果。

**执行优先级**：先验收并尝试昨日 seed9 历史失败交接（#010），再对独立新起点扩样（#009/#011）。seed9 若因历史状态无法精确重建而停止，保存该失败门的证据；不以近似重建补救，也不阻断 #011 的独立筛查。两部分共用下文的待授权总上限，但分别报告，不混合分母。

## 实验 #009：第 0 步检查与真实续跑接口验收

- **日期**：2026-09-23 起；设计冻结后待授权运行
- **要回答的问题**：执行器能否在 Pick 第一个 SAC 动作前停下来检查，`continue` 是否保持原轨迹，真实调整能否到达并续跑？确定性接口通过后，能否在第一条 SAC 动作前取得一次真实、有效的 GPT 决策？
- **run 名称 / ID**：拟用独立 `pick-start-supervision-recovery-20260923/run-v4/independent`，不得写入旧 `near-visible-pick-20260923/run-v3`
- **代码版本**：运行前记录本地执行文件哈希、官方 MS-HAB/ManiSkill 实际导入路径和 Git SHA、原 SAC 检查点/config 哈希；本设计阶段尚无 run 哈希
- **环境**：官方 MS-HAB TidyHouse validation Pick；Python/ManiSkill/PyTorch 版本及实验室 GPU1 UUID 在启动预检记录

### 配置（评测参数）

| 项 | 值 |
|---|---|
| 任务 & 数据划分 | 与 #011 同一批官方 validation Pick 和逐物体 SAC；从新批可见且安全的起点中按 `case_id` 取第一个作排除于效果比较之外的接口样本。#010 的历史交接另做自己的复现与移动门 |
| plan roster / episode 数 | 一条排除于效果比较之外的起点分别做无干预、`check-start-only`、偏航 `move-start-smoke`、平移 `move-translation-smoke`，确定性门通过后再做一次 `periodic_start` 真实 GPT 试运行 |
| 导航策略 | 接口试运行用确定性候选；正式组仅在 GPT 选择调整后，由控制器从当前真实状态沿当时通过官方地面检查的离散路线移动；逐步检查到达、原生终止和力 |
| Pick / Place 策略 | 同一官方逐物体 SAC 原检查点；不训练、不改动作、观察或严格 Pick 判据 |
| 调度器 / 通讯协议 | 接口试运行在 SAC 第一个动作**之前**、`pick_step=0` 作确定性检查。正式 `periodic_start` 在第 0 步及第 10、20 个 **SAC 动作**后调用 GPT；真实移动动作计入官方时限，但不冒充 SAC 检查间隔。正式 `event_start` 在第 0 步调用 GPT，之后沿用 15 个 SAC 动作停滞或累计力达 60% 的事件门槛。每条 Pick 最多三次 GPT 请求、一次调整 |
| observation / policy state | 两张当前相机图、目标和实时状态摘要、当前候选 ID 与路线；无旧 SAC 成败、候选未来结果、Oracle、其他组 GPT 回答。SAC 仍用原始深度历史和官方 42D 状态 |
| skill horizon / episode 上限 | 原 Pick 共用 200 动作及累计力；检查不消耗仿真动作，真实调整每步消耗同一 episode 的动作/力/时限 |
| 模型调用与费用边界 | 确定性门 provider 请求 0；真实 `periodic_start` 试运行最多三次请求，属于 #009–#011 共用的待授权 100 次/USD 2.50/9000 GPU1 进程秒上限。旧批未用余额不自动转用 |
| 随机种子 | 接口起点沿用冻结 reset seed，五组独立重建；记录初态、相机与首个策略观测哈希 |
| 其它关键设置 | GPT 仅可返回 `continue` 或 `reposition(candidate_id)`；协议错误/超时按冻结规则继续。确定性检查无 provider 尝试；真实试运行的第 0 步必须在第一条 SAC 动作前留下请求、有效回答和决策回执，否则不放行扩样。已抓持、严格终止、时限/力耗尽后不调整 |

### 运行顺序与验收门

1. 新代码先做纯本地测试：第 0 步先于 SAC、继续不改变 native 轨迹、第 10/20 步触发、事件组第 0 步触发；旧 `run-v3` 触发模式保持不变。
2. 用一条排除于效果比较之外的起点做 `check-start-only`；它在第 0 步作确定性 `continue`，与同起点无干预逐 native action/info 核对。另分别做偏航和平移的当前真实状态移动、到达、续跑及严格评分接口测试。任一未通过则不启动 GPT 组。
3. 确定性门通过后，在同一排除样本上独立重建并运行一条 `periodic_start` 真 GPT 轨迹；必须有第 0 步请求、有效回答和决策，且发生于 SAC 第一动作前。其严格成败及移动到达照实保存但不计入救回效果。#010 和 #011 的正式 GPT 组同样必须有第 0 步 provider 尝试；#010 历史失败单列，#011 原本成功的最多 4 个入组起点单列成功保持/丧失。

| 完整任务 SR | 不适用 | 主指标是官方严格 Pick |
| 完成物体 | 待运行 | 同上 |

| API 请求 / 费用状态 | 待授权、待运行 | 确定性门 0；真实试运行最多 3 次，逐 provider 尝试和账单状态单列 |

### 观察与结论

- **观察**：尚未运行。旧批 10 个比较起点首次抓持最晚为 episode 第 18 步；旧定期触发在第 20 步且无第 0 步检查，因而配对样本模型调用 0 次。正式协议的第 0 步调用是必要验收，不以缩短间隔代替。
- **异常**：旧批排除样本的真实调整曾出现 80 步未到达；静态路线通过不保证控制器到达，需照实记录。
- **结论**：待运行。此项仅验收接口和真实第 0 步模型暴露；排除样本不纳入救回效果。

## 实验 #010：昨日 seed9 失败 Pick 的同 episode 救回试验

- **日期**：2026-09-23 起；设计冻结后待授权运行
- **要回答的问题**：在昨天可重复失败的 seed9 原站位，GPT 于 Pick 第 0 步开始监督，能否通过**当前状态真实移动**让同一 episode 严格成功？
- **run 名称 / ID**：新批 `run-v4/seed9`；不与 #011 的独立起点合并计算成功率
- **代码版本**：运行前核对昨日交接源码、任务计划、初态、19 步历史前缀、官方运行时和 SAC 检查点哈希；新续跑执行器另记哈希
- **环境**：同一官方 MS-HAB TidyHouse validation Pick；实验室 GPU1

### 配置（评测参数）

| 项 | 值 |
|---|---|
| 任务 & 数据划分 | 昨日 seed9 冻结 Pick 交接。历史同处理 C0 三次在 SAC 第 26 步累计力超限严格失败；离线编辑起点 C1/C2/C3/C5/C6 成功、C4 失败只作研究动机和事后对照，不作为 GPT 输入或在线恢复证据 |
| plan roster / episode 数 | 先做一次当前源码/运行时的 C0 复现与第 0 步确定性 `continue` 对照；复现通过后各运行一次 `periodic_start`、`event_start`，均从同一冻结交接**独立重建**，不把已结束的旧失败 episode 恢复成新 episode |
| 导航策略 | 候选 C1–C6 为**当前状态**局部前/后/左/右 0.20 米及偏航 ±0.35 rad；只有实时地面路径检查通过的 ID 可给 GPT，控制器从当前真实底盘位置移动并逐步测到达。不能以昨日的离线编辑代替移动 |
| Pick / Place 策略 | 原官方逐物体 SAC/checkpoint；从历史初态和 19 步前缀重建到相同 Pick 交接，沿用当时真实任务指针、剩余时限、累计力和物体状态；到达后从新真实观测继续 |
| 调度器 / 通讯协议 | 两个 GPT 组第 0 步均先于 SAC 动作调用；固定组之后每 10 个 SAC 动作检查，事件组之后按 15 个 SAC 动作停滞/累计力 60% 检查；各最多三次请求、一次调整。GPT 只返回 `continue` 或合法 `reposition(candidate_id)` |
| observation / policy state | 当前 fetch_head/fetch_hand 两图、目标、真实力/时限/距离和当时合法候选；**不展示昨日 C1–C6 的 SAC 标签、Oracle、旧 GPT 选 C4 的回答或后来画面** |
| skill horizon / episode 上限 | 以重建交接时的官方 `subtasks_steps_left` 与累计力为起点；历史前缀和共同稳定动作已计入原生状态，移动动作继续消耗同一时限/力，不重置到 200 |
| 模型调用与费用边界 | 本历史子目录拟分配 GPU1 ≤1200 进程秒、最多 6 次 GPT provider 尝试、API 预留 ≤USD 0.15；属于 #009–#011 共用的待授权总上限，无重试。真实单价/账单未知 |
| 随机种子 | seed9；每组独立重放同一初态和前缀，逐项核对输入/任务/初态哈希与交接状态 |
| 其它关键设置 | C0 当前复现若不再严格失败，或前缀、指针、物体、力、相机/策略输入超出冻结容差，停止该历史机制试验并报告重建问题；不从新站位的离线成功标签选择路径。第 0 步候选为空仍允许模型回答 `continue`，并记录无调整机会 |

### 运行顺序与验收门

1. 先实现并核查历史交接到新逐步执行器的适配：重放 19 步，按昨日 C0 同处理写回及一帧稳定；核对初态/前缀和 C0 失败的官方信息、策略输入、动作轨迹与哈希。重建差异不以新的“近似 seed9”替代。
2. 独立重建一条第 0 步确定性 `continue` 对照，要求其 native 轨迹与本批 C0 一致。分别在真实控制器上做可测偏航与平移移动试运行；未到达或原生失败记录为接口未通过，不进入 GPT 效果比较。
3. 冻结有效候选、prompt/schema、源码/检查点与请求预算后，独立运行两条 GPT 轨迹。每条必须有第 0 步 provider 尝试；记录所有回答、实际路线、逐动作时限/力、到达、新观测、续跑与严格评分。
4. 只有 C0 当前严格失败、GPT 在同状态选择合法调整、实际到达、SAC 在同 episode 续跑且官方严格 Pick 成功，才记一条 **seed9 在线救回**。GPT 继续后偶然成功、离线编辑新站位成功、或移动未到达均分开报告。

每条尝试保存逐 native 动作的相机 RGB/深度帧、SAC 观测或可复核哈希、13D 动作、机器人/目标状态、任务指针、剩余步数、累计力和官方 info；第 0 步与后续每次 GPT 的原始输入、候选清单、请求 ID、完整回答、token 用量及实际移动目标/到达误差与动作序列关联。缺少能串起“当前状态→模型决定→真实移动→新观测→SAC 续跑→严格评分”的字段时，只报告观察结果，不发布“救回轨迹”标签。

原始数据写入已有实验室项目盘的独立目录，不创建新租赁存储；本批输出上限拟为 20 GiB，逐 case 检查容量并记录收尾占用。若实验室存储另计费，实际金额待实验室账单对账，不写为零。原始包与结果摘要均记录 SHA-256，保留失败及协议错误尝试。

### 结果

| 指标 | 值（均值 ± population SD，N episodes） | 备注 |
|---|---|---|
| 完成 episode | 待运行 | 历史机制样本 1 个，不并入新样本比例 |
| 完整任务 SR | 不适用 | 主指标为官方严格 Pick |
| 完成物体 | 待运行 | 当前 C0 与两条 GPT 轨迹逐项列出 |
| 每集完成物体 | 不适用 | 仅 Pick 子任务 |
| 环境步数 / 时延 | 待运行 | 前缀、稳定、SAC、移动和模型等待分列 |
| API 请求 / 费用状态 | 待授权、待运行 | 最多 6 次，逐 provider 尝试入账 |

### 观察与结论

- **观察**：昨日 seed9 原站位失败、离线换站位 5/6 成功，提供了值得优先试验的失败状态；旧 GPT 离线选择的是失败的 C4。
- **异常**：旧编辑站位与真正的当前状态控制器移动不同。新执行器的历史交接适配尚待实现和验收，本设计不声称已获得在线救回。
- **结论**：待运行。单个历史案例即使救回，也只证明该 episode 的机制，不估计总体提升。

## 实验 #011：独立失败起点的扩样救回

- **日期**：2026-09-23 起；设计冻结后待授权运行
- **要回答的问题**：对无干预官方 SAC 会严格失败的**同一起点**，GPT 从第 0 步起实时监督，选择继续或真实调整位置后能否在**同一 Pick episode** 中严格成功？
- **run 名称 / ID**：新批 `run-v4/independent` 的独立失败富集面板；昨日 seed9 单列在 `run-v4/seed9`，不混入独立新样本
- **代码版本**：同 #009 的启动前哈希冻结
- **环境**：官方 MS-HAB TidyHouse validation Pick，实验室 GPU1

### 配置（评测参数）

| 项 | 值 |
|---|---|
| 任务 & 数据划分 | 先按 validation scene、物体类别、plan UID 排序，优先每场景一组，再补足 8 个不同 scene×object 组合；不读取 SAC 成败或 Oracle 来生成起点 |

| 导航策略 | 当前状态局部前/后/左/右 0.20 米及偏航 ±0.35 rad 的离散候选；每次调用前重做地面路线检查。移动从**当前真实状态**执行，不预先直接写入候选站位当作救回 |
| Pick / Place 策略 | 与基线同一官方 SAC/checkpoint；到达后从真实新观测继续，同一任务指针、原生时限和累计力不重置 |

| observation / policy state | 同 #009；GPT 不看本起点基线标签、离线候选成败或后续轨迹。基线标签只供预先规定的失败富集入组和事后评分 |
| skill horizon / episode 上限 | 同一官方 Pick 200 动作及累计力；真实调整与 SAC 共用，不能重新给新起点 200 步 |
| 模型调用与费用边界 | #009–#011 拟议**合计**上限：实验室 GPU1 **9000 进程秒**、`gpt-5.6-luna` **100 次 provider 尝试**、每次 ≤2048 输出 token、API **USD 2.50 预留最高额**。执行时拆成不可自动互转的两个授权目录：`run-v4/seed9` ≤1200 秒/6 次/USD 0.15；`run-v4/independent` ≤7800 秒/94 次/USD 2.35。GPT 单 case 进程最多 360 秒，各目录串行受自身余额守卫；额度不足则停并报告未完成配对。#011 最大 14 个比较起点的两组理论请求上限为 84 次，加上 #009 真实接口试运行的 3 次，独立目录尚留 7 次余量。这是待授权提案，不是现有授权或实际支出；实验室单价与实际 API 账单未知。GPU0/RunPod/训练资源不用 |
| 随机种子 | 排序后每 case 冻结官方 reset seed；三组独立重建并核对初态 |
| 其它关键设置 | 最大一次调整、未到达/路径失效/原生失败分开记录；到达后重新观测再调用同一 SAC。结果按失败→成功、失败→失败、成功→失败、成功→成功计数；基线富集样本的比例不用于估计 validation 总体成功率 |

### 运行顺序与验收门

1. 先冻结候选清单、代码/运行时/检查点哈希、可见性判定与预算。对 64 个预定起点逐项记录接受或拒绝；不以 SAC 成败筛起点。
2. 所有接受起点做独立无干预 SAC。严格失败候选再同处理重复一次以检验重现；未重现则单列不入“失败→成功”分母。选入比较的失败/成功 ID 在 GPT 组之前冻结。
3. 第 0 步确定性接口样本必须通过：`continue` 与无干预 native 轨迹相同；偏航与平移调整每一步都令官方时限变化且力不重置；两类均可测到达并续跑。正式 GPT 组第 0 步真实 provider 请求须发生于 SAC 第一动作前。未通过先修复接口，旧失败尝试保留，不混为效果结果。
4. 每个比较起点运行两条独立 GPT 配对轨迹。若 GPT 调整未到达或原生力/时限失败，按严格失败记录；不得把“先前离线候选成功”写成在线救回。至少一条完整的**基线严格失败→GPT 组严格成功**，且第 0 步请求、决策、当前位置移动、到达、新观测续跑、官方严格评分连续可核验，才称为救回轨迹。
5. 预定 64 个起点后如果严格失败数仍为 0，不临时放宽触发器或挑站位；另立新批再扩样本。#010 的 seed9 历史交接独立报告，不填补本面板缺失的失败样本。

原始数据字段与 #010 相同。逐起点报告基线重现、两种调度的严格结果、第 0 步真实请求覆盖、GPT `continue`/调整/协议错误、移动到达、额外动作、力和时间。失败→成功必须进一步分为“确认到达后救回”与“无确认调整的结果变化”；仅前者可称为实时调整轨迹。样本达到上限或共同预算先耗尽即停止，未完成配对不填补或按失败计数。

### 观察与结论

- **观察**：旧批新近距起点无干预 12/12 严格成功，其中 10 个配对样本 GPT 组零唤醒；无法生成在线失败→成功证据。昨日 seed9 的 5/6 是离线换起点后各自重新调用 SAC，不能替代同 episode 救回。
