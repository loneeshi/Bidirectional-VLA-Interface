# 近距离可见 Pick 与 GPT 中途干预：实验设计

胡博士截图提供“缩短 Pick 起点距离、观察新起点表现、考虑定频或失败迹象干预”的研究建议；本次执行协议以用户确认的三组配对、`continue`／真实调整后继续、资金上限与停止规则为准。

## 实验 #006：独立近距起点的官方 SAC Pick

- **日期**：2026-09-23（先按模板冻结设计，后执行并回填结果）
- **要回答的问题**：在物体可见、距物体约 0.8–1.4 m 的独立新起点，官方 SAC 能否完成严格 Pick？
- **run 名称 / ID**：最终官方批次 `near-visible-pick-20260923/run-v3`；`run` 与 `run-v2` 为保留的 AC-DiT 分支诊断，不混入官方配对。
- **代码版本**：正式比较前的 v3 `code-freeze.json` SHA-256 `539e78a1750c34c2e5330b1d7e270efc890f8605c1cfca234645af7b46aa3237`，远端隔离副本 15 个执行文件哈希逐项核对通过；v3 起点清单 SHA-256 `6dd3bd7ec7d5034594980dbbb6937b51170863ee0bbef4c7f5a0206c38e4c42f`。官方 MS-HAB `e9ff3d23496d38e4431c8d913e147ffa007f7f72`、ManiSkill `17121e3f96e3ee3ed0c03610b17f8bc2864617af` 的实际导入路径已核实，检查点/config 与原始 plan 哈希逐 case 校验。
- **环境**：MS-HAB TidyHouse validation Pick、实验室 GPU1；Python、ManiSkill、PyTorch 版本在预检时读取并落盘。

### 配置（评测参数）

| 项 | 值 |
|---|---|
| 任务 & 数据划分 | 官方 TidyHouse validation Pick；不复用 9/22 交接状态或候选 SAC 标签 |
| plan roster / episode 数 | 按 `(scene, object_category, plan_uid)` 排序，选前四个不同 scene×物体类别；每组六个预定近距位姿，最多 24 个有效起点。所有被拒候选仍记录。 |
| 导航策略 | 无；起点由 reset 后的诊断性位姿设置产生，不能解释为导航可达或在线恢复。 |
| Pick / Place 策略 | 同一官方逐物体 SAC `rl_per_obj` Pick 检查点；不训练，不改 SAC 动作、控制器或成功谓词。策略输入按官方字段从当时真实状态重建 42D，原始深度历史不变；早期 AC-DiT 分支额外给出 51D 状态，已单独归档。 |
| 调度器 / 通讯协议 | 无 GPT；先做起点可行性、原站位 SAC 及重复性测量。 |
| observation / policy state | 原始深度历史及从真实机器人/物体状态重建的官方 42D SAC 字段；另外保存起点头部、手部 RGB 与哈希。严格加载原检查点验证 42D 合约。 |
| skill horizon / episode 上限 | 官方 Pick 最多 200 动作；共同的一帧全零稳定动作也计入官方时限及累计力。 |
| 模型调用与费用边界 | #006 不调用 GPT。用户已授权本批 GPU1 累计 ≤14400 秒、GPT ≤120 次、每次输出 ≤2048 token、API 预留 ≤USD 3.00；实验室单价未知。GPU0、RunPod 均不用。 |
| 随机种子 | 每个 plan 的 reset seed、build/spawn 索引及 RNG 状态在任何 SAC 结果出现前冻结。 |
| 其它关键设置 | 半径 0.8、1.1、1.4 m × 方位角 ±π/6，共六个面向目标中心的位姿；只改 reset 后的底盘 XY/yaw，保留物体与其它关节。目标须在头部相机可见，手部相机可用；官方地面端点、稳定漂移 ≤0.03 m、持物/任务指针/累计力均通过。可见性和场景路径证据须在任何 SAC 调用前确认。 |

### 执行与验收门

1. 冻结候选、源 plan、checkpoint/config、reset、原始起点状态和双相机图像哈希；对每个候选记录通过或拒绝原因，不依据 SAC 成败补样。
2. 每个 scene×物体组的第一个有效起点作为接口试运行，其余作为配对比较。有效起点少于 12 个或不足两个不同组时，停止方法比较，仅报告起点生成可行性。
3. 从独立 reset 重建同一试运行起点，先检查稳定后的状态、动作轨迹和官方结果能否重复；不一致者标记 `start_not_reproducible`，不进入三组配对。
4. 对合格起点运行无干预 SAC。主指标为官方严格 Pick；首次抓持、TCP 距离、最终持物、累计力、失败/超时及动作步数单列，不用“曾抓持”替代成功。

### 结果

| 指标 | 值 | 备注 |
|---|---|---|
| 候选起点 / 有效起点 / 拒绝原因 | 24 / 12；8 个官方地面外，4 个目标可见性无法确认 | 12 个有效起点来自两个 scene×物体组；四组属于同一场景文件，场景多样性有限。 |
| 可重复起点 | 接口试运行两组通过；同一起点检查后继续与基线原生动作/info 轨迹哈希相同 | 冻结清单按独立进程重建；图像哈希复核。 |
| 官方严格 Pick | 12/12；配对部分 10/10，population SD 0 | G1-P1、G2-P1 为试运行，不计入配对效果。 |
| 抓持、累计力、时限与失败原因 | 配对样本两组的首次抓持均不晚于 episode 第 18 步 | 逐 case 原始轨迹及辅助审计保留；无干预各起点最终严格成功。 |
| GPU 时间 / API 请求 / 费用 | 全批 GPU1 进程墙钟 2599.0498/14400 秒；#006 GPT 0 | 含保留的分支诊断、v3 官方批次与接口试运行；实验室实际费用未知。 |

### 观察与结论

这些独立近距起点上，官方运行时与官方 SAC 检查点可完成严格 Pick。样本按固定排序导致四组只覆盖同一场景文件，其中两组有效；不能推断完整 TidyHouse、导航交接或在线恢复成功。早期 51D 环境在加载 42D 检查点时失败，随后 v2 虽重建了官方 42D 策略字段，但实际导入 AC-DiT 分支；只有 v3 在纠正导入路径后计为官方环境结果。

## 实验 #007：每 20 步检查的 GPT 中途干预

- **日期**：2026-09-23（已运行）
- **要回答的问题**：对同一近距起点，定期让 GPT 决定继续或真实调整站位，能否相对无干预 SAC 净增加严格 Pick 成功数？
- **run 名称 / ID**：与 #006 同批，setting=`periodic`。
- **代码版本 / 环境**：与 #006 相同；任何版本差异均取消配对。

### 配置（评测参数）

| 项 | 值 |
|---|---|
| 任务 & 数据划分 / roster | #006 中通过可重复性门、未用于接口试运行的同一批起点；每个 setting 从独立 reset 重建。 |
| 导航策略 | 无；GPT 选择调整时，底盘从**当前实际位置**由 Fetch 控制器移动并测量到达。 |
| Pick / Place 策略 | #006 相同 SAC；到达后用新真实观测继续同一 Pick，不重置策略检查点、物体、任务指针、官方时限或累计力。 |
| 调度器 / 通讯协议 | SAC 每执行 20 个 Pick 动作且尚未抓持/成功/失败时唤醒 GPT；最多三次检查、一次调整。GPT 只输出 `continue` 或 `reposition(candidate_id)`。 |
| observation / policy state | 两张当前相机图像、目标描述、持物状态、TCP 距离、累计力/上限、剩余时限、触发原因和当前可行候选；候选成败及未来画面不可见。SAC 输入保持官方原样。 |
| skill horizon / episode 上限 | 同一官方 Pick 200 动作；调整过程每一步均计时、计力、计入轨迹。 |
| 模型调用与费用边界 | `gpt-5.6-luna`，每起点最多三次、每次最多 2048 输出 token；全批最多 120 次、API 预留最多 USD 3.00，调用前已获授权。密钥留本机，SSH 文件桥接有持久请求认领。 |
| 其它关键设置 | 只在未持物、官方 Pick 未终止、累计力未超限时可调整。候选为当前位置局部前/后/左/右各 0.20 m、偏航 ±0.35 rad；只提供当前状态下通过官方地面连续路径检查的候选。到达误差 ≤0.04 m / 0.06 rad，连续三次检查稳定；移动中的接触和累计力逐步记录。 |

### 结果

| 指标 | 值 | 备注 |
|---|---|---|
| 严格 Pick 相对无干预的净增减 | 配对 10/10 对 10/10，净 0 | 十组都在第 20 步前已抓持，故无真实 GPT 暴露。 |
| GPT 检查 / 调整 / 到达 | 配对 0 / 0 / 0 | 官方 v3 排除样本 G1-P1 唤醒 1 次、GPT 选 C2，移动 80 步未到达，严格失败。 |
| 额外动作、力、时延与 API 用量 | 配对额外调整动作 0、API 请求 0 | 官方 v3 G1-P1 接口样本 1 次真实请求；80 个移动动作进入同一 episode，原始轨迹保留。 |

### 观察与结论

配对样本无法衡量 GPT 效果，因为全部未唤醒。官方 G1-P1 接口样本实际执行了 GPT 的 `reposition(C2)`，但 80 步未到达；其基线成功、模型组失败，只能作为潜在损失的个例。无模型的 `continue` 检查与基线逐动作一致，C5 偏航调整测得到达并续跑；两条真实分支均验收。AC-DiT 分支另有一次 GPT `continue` 与 `reposition(C6)` 到达后续跑的保留诊断，不能当作官方环境效果。

## 实验 #008：事件触发的 GPT 中途干预

- **日期**：2026-09-23（已运行）
- **要回答的问题**：用可测的停滞或力风险触发 GPT，能否在相同请求上限下优于定期检查与无干预？
- **run 名称 / ID**：与 #006 同批，setting=`event`。
- **代码版本 / 环境**：与 #006–#007 相同。

### 配置（评测参数）

| 项 | 值 |
|---|---|
| 任务 & 数据划分 / roster | 与 #007 完全相同的配对起点。 |
| 导航、Pick、观测、输出、horizon | 与 #007 相同。 |
| 触发器 | 连续 15 个 Pick 动作 TCP 到目标距离改善 <0.03 m，或官方累计力达到 5000 上限的 60%（3000）；最多三次 GPT 检查、一次真实调整。已抓持、成功、失败或耗尽时不唤醒。 |
| 模型调用与费用边界 | 与 #007 相同的模型和每起点上限，共享已授权的 120 次/预留 USD 3.00 上限。 |
| 其它关键设置 | 同一触发原因只按冻结规则触发；无有效路径候选时 GPT 仍可选择继续，但不得输出任意坐标。 |

### 结果

| 指标 | 值 | 备注 |
|---|---|---|
| 严格 Pick 相对无干预和定期检查的净增减 | 三组配对均 10/10；事件组净 0 | 无失败→成功或成功→失败。 |
| 触发原因、检查与调整次数 | 配对 0 次触发、0 次检查、0 次调整 | 十组均在事件门槛成立前抓持。 |
| 额外动作、力、时延和 API 用量 | 配对调整动作 0、API 请求 0 | 排除的 G1-P1 接口样本停滞触发 1 次，GPT 选 C4，移动 80 步未到达，严格失败。 |

### 观察与结论

固定事件门槛在这十个近距样本上没有唤醒 GPT，因此本批不能评估事件触发的 GPT 决策质量。G1-P1 接口样本的 C4 路线通过静态地面检查，但控制器在 80 步内未到达，体现了地面路径许可与真实可执行到达的区别；不能算恢复成功。

## 共用接口与执行门

GPT 输出只允许 `{"action":"continue","candidate_id":null,"reason":"..."}` 或 `{"action":"reposition","candidate_id":"C1","reason":"..."}`；候选 ID 必须来自当次合法列表。prompt 和 JSON schema、模型版本、图像细节、请求 ID、失败处理、源码哈希在正式比较前冻结。所有模型调用按真实 provider 尝试记账。

中途调整必须先通过：原 SAC 暂停前后状态连续、每个调整动作令官方剩余步数减一、累计力不重置、官方地面连续路径检查、移动中逐步监测原生失败与力、到达测量、到达后同一 SAC 继续，以及纯检查不改变基线轨迹。静态地面三角网只证明底盘路线在地面内，**不证明全身或动态无碰撞**；因接触或原生失败中止的移动单列为调整失败，不能当作成功到达。

资金门已于执行前取得用户授权：GPU1 累计 ≤14400 秒；`gpt-5.6-luna` ≤120 次、每次输出 ≤2048 token、API 预留 ≤USD 3.00。实际 GPU1 进程墙钟 2599.0498420 秒，剩余 11800.9501580 秒；六次 provider 请求均在排除的接口样本中（分支诊断四次、官方 v3 两次），合计 2761 输入/284 输出 token，预留 USD 0.15，剩余 114 次与预留 USD 2.85。预留不是实际收费，API 实收与实验室单价/费用仍待账单对账。GPU1 收尾 15MiB/0%，无本批进程；GPU0 未操作，未新建 RunPod 或训练资源。

原始证据：实验室服务器工作区 `runs/near-visible-pick-20260923/run-v3/` 的 `final-score.json`、`aux-audit-final.json`、各 case `events.jsonl`、图像/回执和桥接请求；本地 `repo/Bidirectional-VLA-Interface/runs/near-visible-pick-20260923/v3/` 的镜像。官方 v3 证据包 SHA-256 `14cc8450c1ede654a71566c17514b417e56e10abed3ef5d11aab6ad620341e67`。分支诊断分别保留在 `run`、`run-v2`，不得合并评分。逐次请求与预算见项目财务分账 `ledger-near-visible-pick-20260923.json`。
