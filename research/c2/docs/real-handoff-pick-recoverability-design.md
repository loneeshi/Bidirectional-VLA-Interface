## 实验 #待编：真实导航交接点的第 0 步可救回性

- **日期**：2026-09-24 起草。
- **要回答的问题**：在真实 PPO Navigate 切换到官方逐物体 SAC Pick 的起点中，无干预 Pick 失败有多少能通过预先固定的底盘动作，在同一 episode 内合法移动、真实到位并获得官方严格 Pick 成功？
- **run 名称 / ID**：待冻结；本草案不是运行记录。
- **代码版本**：待冻结项目、MS-HAB、控制器、SAC checkpoint 与样本清单哈希。旧实验结果只用于设计，不进入新批次分母。
- **环境**：TidyHouse validation、项目固定 PPO 导航、官方逐物体 SAC、实验室 GPU1；运行时版本与 GPU UUID 在授权前预检中登记。不得使用 GPU0、RunPod、训练或付费模型 API。
- **主线时间边界**：建议把 C2 作为第 2 步内不超过七个日历日的有界诊断；到期或完成可救回性统计（先到者为准）即决定继续 GPT 对比、改进导航交接或返回 TAPT 验收。此建议尚待用户确认，不自动放行后续批次。

### 配置（评测参数）

| 项 | 草案值与冻结要求 |
|---|---|
| 任务 & 数据划分 | 事先按 plan UID 排序并锁定至多 120 个 validation 计划。只采集该计划原生执行中的**首次 Navigate→Pick 交接**，每计划最多一个起点；导航没有完成的计划和原因仍入清单，不冒充 Pick 失败。目标取得至多 60 个有效交接起点，按实际数量报告；记录场景、物体类别和重复场景，不能把不同计划自动称为独立场景。禁止 teleport 或手工设置近距起点。 |
| plan roster / episode 数 | 先只读盘点现有真实交接和原始轨迹，能验收身份与评分的既有基线优先复用；对缺失的有效交接才新增无干预 SAC。失败起点至少再做一次同处理复核，核对初态和动作／终止一致性。仅对可重复的失败起点执行真实动作扫描；不复现者单列。前 12 个有效交接作为同一预定清单的吞吐预检，最多扫描其中前 2 个可重复失败，且不因结果好坏替换样本。余下部分须另定资源上限后才能执行。 |
| 导航策略 | 使用原生 PPO Navigate 的真实完成状态。保留交接瞬间的物理状态、任务指针、剩余 Pick 时限、累计力和相机；每个候选从这个相同状态独立重建。导航失败不进入条件于交接的 Pick 分母，但必须报告其比例。 |
| Pick / Place 策略 | 同一官方逐物体 SAC，未调整基线与所有候选共用 checkpoint、观测、评分和 200 步官方 Pick 限制。Place 不适用。所有刹车、调整、续跑动作计入原 episode 时限和累计力；不重置物体、任务指针或失败状态。SAC 续跑后仍可控制底盘，记录其实际运动。 |
| 候选动作 | **主库 9 项**：原地转向 ±0.10／±0.20／±0.35 rad（6）；沿当前朝向前进 0.10／0.20 m（2）、后退 0.10 m（1），固定顺序。另预列相对当前朝向左／右平移 0.10 m（2）为**扩展库**；它们需要非全向底盘的“转向—行驶—转回”控制器。只有横向控制在运行前单独验收并冻结，才报告 11 项扩展库结果；否则主库照常执行，横向两项列为未纳入，不把 9 项结果称为 11 项上限。所有动作、坐标系、上限和来源代码在运行前锁定；连续动作空间无法“全部枚举”。 |
| 调度器 / 通讯协议 | 无 GPT。每个失败起点的全部候选先按同一静态路线检查，再从相同交接状态分别真实执行，通过动态到位后从新观测续跑 SAC 至官方终止。路线拒绝、未到位、官方失败与预算删失分开记录；不得拿基线或其它候选结果来选择／调整候选。 |
| observation / policy state | 记录原生头／腕相机、base_link 与目标相对几何、TCP 到目标距离、机器人总力与目标接触力，但这些诊断量不改 SAC 输入。可达性审计须区分原始交接时刻与 Pick 已执行多步的历史快照；夹爪到物体中心距离不能直接判定手臂运动学可达性。 |
| skill horizon / episode 上限 | 官方任务时限、力上限与终止判据原样保持；每个局部动作另有冻结的单次执行上限及实际到位容差。任何路线检查或控制器修改只用于新冻结版本，不回写旧轨迹。 |
| 模型调用与费用边界 | 模型／API 请求 0。参考旧 #015 的 39 个进程约 2069 GPU1 进程秒，均值约 53 秒；新批需要真实导航前缀，不能按此均值直接承诺总时长。**建议仅首段预检申请 GPU1 累计最多 3600 进程秒、单进程最多 300 秒；此数字尚未获得授权。** 完整批次上限待预检吞吐后另行提出。实验室单价、币种与实际金额未知，旧实验余额不得转用。 |
| 随机种子 | 计划及 reset seed 从锁定清单读取；每起点各条件独立同处理重建。起点状态哈希、导航交接事件、SAC 首输入、源码与 checkpoint 哈希为准入门。 |
| 其它关键设置 | 静态路线合格不等于真实可到达或全身无碰撞。纯转向的静态预览与网格外路径门已有本地 CPU 修正，须在本批源码中回归验证；实际到位与真实接触在每条候选中验收。横向动作接口若未通过，只影响扩展库，不阻断主问题。 |

### 指标、判读与停止门

| 指标 | 定义 |
|---|---|
| 交接后的基线成功率 | 无干预严格 Pick 成功起点数／全部有效真实交接起点数。导航未交接、重建不一致单列。 |
| 已证实可救回失败比例 | 至少一个候选同时满足**路线合法、实际到位、同 episode 官方严格成功**的起点数／可重复的基线失败起点数；同时报告因接口失败或预算未测而无法下阴性结论的起点数。 |
| 此有限库的 Oracle 成功率 | （基线成功起点数＋已证实可救回失败起点数）／全部可评分交接起点数。主结果只对应**9 项主库、Pick 第 0 步、当前控制器**；若两项横向动作事先验收，再另报 11 项扩展库。二者都不是所有可能动作或 GPT 的效果。未完成扫描时同时报告可证实下界和未决上界，不填写虚假的精确值。 |
| 动作接口覆盖 | 按候选逐级报告：路线接受率、动态到位率、获得官方终局率、严格成功率；先判断“能不能执行”，再判断“能不能救回”。 |

1. CPU 阶段先清点现有 16 计划面板、A1/A2 和后续在线日志可复用的交接／基线，写明缺口；再冻结新增真实交接提取代码、计划 ID 清单、9 项主库及可选的 2 项扩展动作、几何与动态到位测试、单进程及累计时长守卫、输出哈希和独立账本。确认 GPU1 空闲及资源规则，并取得**本批明确授权**后，才允许运行首段预检。
2. 前 12 个有效交接只用来量测交接取得率、重建一致性和进程吞吐；按预定顺序扫描最多 2 个失败起点。若无法复现起点、动态动作多数不能到位或时长超预算，停在接口／覆盖结果，不推断不可救回比例。
3. 完整批次的授权上限须根据预检时长和失败率重算；不能把“60 个交接”当成“60 个失败”。至少报告原始分子分母、按场景／物体的覆盖和不确定区间，不预称 40–60 对足以检测 GPT 约 15 个百分点的收益。若失败起点过少，只报告探索性估计。
4. “可救回比例低于 20%”是后续策略选择的**候选止损线**，只有动作库覆盖充分、未决数量少且不确定区间也支持低比例时才可裁决；不能仅凭小样本点估计停止。若动作库接口覆盖不足，先修执行能力，不能把接口失败解释为 Pick 在物理上无法救回。
5. 只有本批观察到足够多、动作需求不同的可救回起点，才另立 GPT／固定前移／可达性启发式／随机动作的配对比较。未来 GPT 输入不含 Oracle 标签；同时报告救回与误伤，净收益以全部原始交接起点为分母。

### 观察与结论

- **观察**：尚无新数据。
- **异常**：seed4 现有 1.42 m 数据来自已执行 161 个 Pick 动作后的快照，不能当作 Navigate→Pick 第 0 步；需要只读核对真正交接瞬间的几何／运动学可达性。既有 Teleport 与固定导航的完整任务差异也不能单独归因于站位。
- **结论**：尚未运行；旧 #015 仅证明 seed8／seed4 的有限候选未找到救回，不能估计真实交接分布的总体比例。
