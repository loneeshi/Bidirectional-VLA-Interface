### 放行顺序、停止规则与判读

1. 只读核对实际 SAC 训练起点来源；若只能取得上面的 train-spawn 代理，记录 `training_support_unknown`。冻结执行代码、prompt/schema、请求图像编码、checkpoint、运行时和源初态哈希。当前 9 个 CPU 检查仅验收几何/路由实现，不算真实转向到达或避障验收。
2. 获得本实验独立资金授权后，先做 A 与 B。A 必须复现严格失败；B 不发 provider 请求，所有 SAC 动作、图像、官方 info 与 A 逐步相同。若任一初态身份/对照失败，停止 C/D，只报告重建或接口故障。四个运行单独重建，拟定各进程硬上限依次 350/350/1000/1800 秒，总和 3500 秒，另预留 100 秒给失败/启动开销；累积上限 3600 秒。
3. C/D 的任何平移先经冻结地面路线检查；纯转向使用本地修正的纯转向入口。局部控制器每步检查官方终止、受力和到达。**未到达**时记录真实落点并终止该干预分支为 `movement_not_arrived`，不把落点效果归给提议站位；路线被拒、超时或耗尽上限时记录对应机制失败，不人工代选动作。
4. D 每次请求最多一次 provider 尝试。模型可返回 `continue` 或 `request_reposition`，后者可提出范围内 `move(0.005–0.30 m, -π–π)` 或 `turn(0.005–0.52 rad)`；无效提议带具体错误回传。API/资源上限、官方终止、输入缺失立即停；预算提前终止记删失，不计严格失败。所有原始请求、回答、token、动作、图像、力与官方 info 按时间索引保留。
5. 只有 A 严格失败、D **先运行至少一个 SAC 动作并看过真实执行反馈**后选择合法调整、控制器实际到达、后续 SAC 在同一 episode 续跑且官方严格 Pick 成功，才称 seed8 个案**中途在线救回**。若 D 在第 0 步移动后成功，单列为起点调整；若 D 继续后成功、C 也成功，分别报告，不能单独归因 GPT。单 seed 即便救回也仅是机制见证；无救回不能断言方法总体无效。
