# 给胡博士看的 C2 闭环 Pick 演示与失败分析

截至 2026-09-30 UTC。这里讨论的是 **E1-B/E1-B2 特权试点**：Astra 在首次请求中获得目标包围盒中心相对尝试起点机器人的坐标，之后通过头部和手部 RGB-D、里程计与工具反馈决策。它不能证明 Astra 已经单靠视觉找到目标，也不是无特权主条件的结果。每例从交接快照开始，官方最多 200 个环境步；只有抓住、回休息位、静止且不触发力限制等全部满足，才算严格 Pick 成功。

## Trajectory 实际是什么样？

它不是 SAC 那样每步输出一整个关节动作，而是 Astra 每轮看四路图和里程计，选择一条工具命令；程序用官方动作通道把它执行若干环境步，再返回新观测。底盘命令是先转后直行，末端命令由机器人自身 IK 执行。

| 案例 | 关键指令轨迹 | 官方结局 |
|---|---|---|
| 5，成功回归 | 张开夹爪 → 底盘前进 0.20 m（实际约 0.196 m，22 步）→ 多次 `move_to` 与闭合/张开调整 → 再闭合 → 抬臂 → `return_to_rest`。共 13 次调用、146 步。 | **严格 Pick 成功**。说明接口和一条完整闭环轨迹可以成功；不代表新样本通过。 |
| 14/26/42，新样本 | 首条均请求不转向、直行 0.85 m；分别在第 33/46/25 步被官方累计力上限终止，指令均未到位。 | **3 例均失败**。评估端分别记录底盘与桌子、沙发、沙发接触。 |
| 1，新样本 | 首条请求前进 0.55 m 并到位，随后多次末端对准和夹爪调整，最后调用 `return_to_rest`；共 14 次调用、200 步。 | 末帧虽 `is_grasped=true`、`robot_rest=true`，但 `ee_rest=false`、`is_static=false`，**严格失败**。 |
| 55，加入方法指导 | `check_path` 拒绝远处抓取 → 前进 0.25 m（实际约 0.245 m）→ 再请求前进 0.30 m，实际只走约 0.042 m 即力超限。 | **严格失败**；评估端记录底盘与桌子接触。 |
| 58，加入方法指导后单次授权重试 | `check_path` → 四次各 0.30 m 前进且到位 → `check_path` → 张开夹爪 → `move_eef_chunk` 用满 60 步仍距目标约 0.110 m → `move_to` → 闭合。 | 共 200 步；未抓住、未回位，**严格失败**。里程计全程净平移约 1.320 m，包含初始停稳期间的位移，不能简单说四条命令走了 1.320 m。 |

## 主要问题、失败因为什么？

目前最直接的问题不是“能否发出底盘动作”：底盘工具契约和接口检查已经通过，5 号严格成功，58 号也能完成四段前进。**尚未证明模型能稳定地从受遮挡的低分辨率视角，判断整个底盘宽度范围内是否可通行，同时为抓取、回位留够 200 步。**

1. **长直行撞家具。** E1-B 的 14/26/42 首条均是 0.85 m 直行，途中分别接触桌子或沙发并触发官方累计力限制；11 号回归首条 1.15 m 前进也触发力限制。目标坐标在首轮已给出，所以这些轨迹不能作为“从图像准确估计目标距离”的证据。它们显示的是靠近目标时对通道净空的决策失败；当时没有逐条 note，无法确定模型心里依据了哪一块图像。
2. **分段也可能误判通道。** 55 号的 note 明说中心通道部分被遮挡，仍从可见的地面窄条推断可通行并发出下一段 0.30 m；实际约 0.042 m 后碰桌。指令按计划执行到官方终止，证据更支持模型把局部可见地面当成足够的底盘净空，而不是控制器无故偏离。这一归因同时有事前 note、RGB-D、里程计和评估端接触记录；它仍不能证明换个动作一定成功。
3. **抓取与回位的步数规划不足。** 58 号未碰撞，但到执行长末端动作时只剩 78 步；该动作 60 步未到位，再下降 10 步、闭合 8 步，官方 200 步耗尽，既未抓住也未回位。模型 note 已承认预算紧，反思也承认导航和手臂耗步过多。1 号则抓住物体后未满足末端回位和静止判据。

视角与分辨率可能影响判断，但还没有同一闭环案例的 128×128 对 256×256 配对实验；不能把失败单独归咎于分辨率。旧离线配对的目标距离平均绝对误差由约 0.557 m 降至 0.471 m，但不确定区间跨零，且不能恢复被机器人自身挡住的表面。[视野和分辨率核对](../diagnostics/2026-09-30-eef-visible-obstacle-audit/README.md)详列了证据边界。

**结果边界：** E1-B 的新样本 **0/4**、回归样本 **1/3**，七例均完成。E1-B2 仅有 55 失败和 58 单次重试失败；61 及四个配对样本未启动，最初 58 请求还发生过 API 删失，因此不能写成完整的 `0/3` 或 `0/4`。接口通过、某些轨迹能执行、官方严格 Pick 成功、整项研究完成，是四个不同判断；目前只有 E1-B 回归 5 号取得严格 Pick 成功，研究问题仍开放。
