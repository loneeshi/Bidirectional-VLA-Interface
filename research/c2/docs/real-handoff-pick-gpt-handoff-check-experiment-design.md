# 真实交接 Pick 前 GPT 站位检查（第三步）：运行前设计草案

按[实验日志模板](../../../docs/log/TEMPLATE.md)组织。**状态：条件性草案。只有[第二步救回上限扫描](../../../docs/design/real-handoff-pick-rescue-upper-bound-experiment-design.md)达到"有提升空间"档（确认救回 ≥ 4/14，或灰区扩样后达标）才启动冻结。尚未冻结提示词、门控阈值、样本清单和资源授权，也未运行。**

本实验是 C2 三步中的第三步，问的是：**在 SAC 开始前让 GPT 检查交接站位，只在它判断会失败时才调整底盘，能否在全部真实交接上带来净提升？** 关键约束有三条：

- **必须胜过不用 GPT 的对照**：固定动作、规则门控、几何启发式都要一起比；
- **净收益以全部交接为分母**，救回和误伤都算；
- **在未见过的新交接上验收**，第一、二步的 60 个交接只能用作开发集。

之所以把 GPT 放在 Pick 开始前，而不是执行中：普查中可重复的底盘碰撞多在 Pick 第 12–14 步就因累计力超限终止，执行中第 10／20 步的检查来不及；#011 也显示对原本会成功的轨迹做中途调整会造成误伤。

## 实验 #待编：Pick 前站位检查的配对比较

- **日期**：2026-09-26 起草。
- **要回答的问题**：在新的真实交接上，GPT 门控加动作选择的严格 Pick 成功率，是否高于无干预基线，并且不低于不用 GPT 的规则与启发式方法？GPT 该动时是否动、不该动时是否不动？
- **run 名称 / ID**：待冻结。
- **代码版本**：待冻结。复用普查与第二步的检查点、控制器、候选库、路线检查与到位检查哈希；新增门控规则、启发式、GPT 输入编译器与提示词的 SHA-256。
- **环境**：同普查；实验室 GPU1。GPT 调用经 OpenAI API，模型名与版本在运行前锁定。

### 数据划分

| 集合 | 来源 | 用途 |
|---|---|---|
| 开发集 | 普查的 60 个交接（清单位置 0–63），以及第二步的救回标签 | 设定门控阈值、选出单一最佳固定动作、调试提示词格式和 GPT 接口。**可以看结果调参。** |
| 验收集 | 沿同一 UID 字典序清单继续：位置 64–119，再扩展冻结位置 120–239（从 1,000 个 validation 计划中按同一规则续取） | 目标 **120 个有效交接**，下限 80 个。所有规则、阈值、提示词在看到验收集任何结果前冻结；验收集只运行一次，不回头调参。 |

验收集规模的依据：按普查约 33% 的失败率，120 个交接约有 40 个失败。如果某方法净救回约 10 例、误伤约 2 例，精确 McNemar 检验大致可以检出。80 个交接只能检出更大的效应，此时如实报告为探索性结果。

### 对照组（每个交接配对，同一快照独立还原）

| 组 | 何时干预 | 选哪个动作 | 作用 |
|---|---|---|---|
| **A0 无干预** | 从不 | — | 基线 |
| **A0′ 无干预复跑** | 从不 | — | 随机噪声下限：A0 与 A0′ 的不一致数就是"什么都不做"时的配对差异，任何方法的效应都要超过它 |
| **A1 固定动作** | 每个交接都做 | 开发集上的单一最佳固定动作 | 无条件干预的收益与误伤 |
| **A2 规则门控＋固定动作** | 确定性规则判断为高风险时 | 同 A1 | 测"何时动"的价值 |
| **A3 规则门控＋几何启发式** | 同 A2 | 按几何规则选：离目标远则前移，离障碍近则后退或转离；具体规则在开发集上冻结 | 不用 GPT 的最强对照 |
| **A4 GPT 检查** | GPT 自己判断 | GPT 从已通过可行性预检的候选中选，或选择继续 | 主实验组 |
| **A5 GPT 判断＋规则决策**（次级） | GPT 给出成功概率低于阈值时 | GPT 给分最高且已通过预检的候选 | 应对 GPT 一直选"继续"的问题；阈值在开发集上冻结 |

**节约规则**：门控组在不干预时，结局就等于 A0，直接复用 A0 那一次运行，不重跑。所以只有真正干预的交接才产生额外仿真。

### 配置（评测参数）

| 项 | 草案值与冻结要求 |
|---|---|
| 任务 & 数据划分 | 见上；验收集清单与哈希在运行前冻结。 |
| plan roster / episode 数 | 验收集每个计划先跑原生导航，取得交接快照；A0、A0′ 各跑一次 SAC；A1 每个交接跑一次；A2–A5 只在干预时额外跑。 |
| 导航策略 | 官方 PPO Navigate，同普查。 |
| Pick / Place 策略 | 官方逐物体 SAC；底盘动作计入同一 episode 的 Pick 时限与累计力，同第二步。 |
| 候选动作 | 第二步冻结的 11 项主库（扩展库 2 项仅在第二步已验收时加入）。GPT 只能从**已通过静态路线预检**的候选里选，每个候选附预期终点与碰撞余量。 |
| 调度器 / 通讯协议 | 每个交接的 Pick 第 0 步调用 GPT 一次，零重试；输出结构化 JSON：`p_success`（继续下去的成功概率）、`decision`（`continue` 或某个候选 ID）、每个候选的分数、依据。A4 执行 `decision`；A5 按阈值规则执行。执行被拒或未到位的结果如实记录，不补第二次调用。 |
| observation / policy state（GPT 可见） | 头／腕相机图像；交接几何量（底盘–目标距离与方位、目标高度、底盘到最近障碍距离，若可导出）；候选列表与预检结果。**不提供**第二步的救回标签、A0 结局或任何事后信息。"继续"与各候选在提示词中地位平等，不写作默认选项，顺序随机化并记录。 |
| 门控规则（A2/A3） | 由开发集的第 0 步协变量设定，例如底盘–目标距离、目标高度、到最近障碍的距离。阈值在开发集上冻结，并报告其在开发集上的召回与误报。 |
| skill horizon / episode 上限 | 官方值不变。 |
| 模型调用与费用边界 | 验收集最多 120 次 A4 请求，加 120 次 A5 请求（若 A5 与 A4 共用同一次调用的输出，则共 120 次）；开发集调试最多 60 次。按 A3 历史预留（每请求约 USD 0.025）估算，**建议 API 上限 USD 10**。GPU1：验收集导航与 A0/A0′/A1 约 120 ×（44＋3×40）秒 ≈ 20,000 进程秒，加干预组额外运行，**建议分段申请：开发集接口调试 1,800 秒，验收集主批初估 28,800 秒以内**。以上均未获授权；实验室货币成本未知，按独立账本登记。 |
| 随机种子 | 清单与 reset seed 冻结；GPU 物理随机性由 A0′ 量化。 |
| 其它关键设置 | 模型名、提示词、图像分辨率、推理强度在验收前冻结。GPT 调用失败（超时、格式错误）记为"继续"并单列，不重试、不排除该交接。 |

### 指标

| 指标 | 定义 |
|---|---|
| **主指标：净收益** | 各组相对 A0 的配对差：救回数（A0 失败→该组成功）减误伤数（A0 成功→该组失败），以全部有效交接为分母；精确 McNemar 检验，附 95% 区间。**必须同时超过 A0 与 A0′ 之间的不一致数。** |
| 关键比较 | A4 对 A3（GPT 是否胜过最强非 GPT 对照），A4 对 A2（选择动作是否有价值），A2 对 A1（门控是否减少误伤）。 |
| 干预质量 | 干预率；干预精确率（干预的交接中 A0 失败的比例）；干预召回率（A0 失败的交接中被干预的比例）；A0 失败时 GPT 选"继续"的比例。 |
| 校准（A4/A5） | GPT 给出的 `p_success` 与 A0 实际结局的 Brier 分数和分箱校准曲线。 |
| 执行 | 所选候选的路线接受率、到位率。 |
| 成本 | API 请求数与费用、GPU1 进程秒。 |

### 判读（写在运行前）

- **GPT 有价值**：A4（或 A5）净收益为正且检验显著，并且相对 A3 的配对差也为正。只胜过 A0、不胜过 A3，只能说"Pick 前干预有用"，不能归功于 GPT。
- **GPT 不劣于启发式**：只胜过 A0、与 A3 打平，结论是"GPT 可作为不需手写规则的替代方案"，不宣称优势。
- **无净收益**：A4 的救回被误伤抵消，或干预召回很低（大部分失败 GPT 都选了继续），分别报告原因。后者说明需要改进判断信号或采用 A5 的决策分离。
- **验收集不足 80 个交接，或 A0/A0′ 不一致数过大**：只报告探索性结果。

### 运行门与停止规则

1. **启动前提**：第二步达到"有提升空间"档，并且其判读已经写入日志。
2. **开发集阶段（需授权）**：在普查的 60 个交接上冻结门控阈值、单一最佳固定动作、启发式规则与提示词。GPT 在开发集上只用来验证接口与输出格式，结果可以看，但冻结后不再改。
3. **验收集阶段（需另行授权）**：冻结清单后按位置顺序执行，各组全部运行后统一评分，中途不看组间比较，不提前停止。
4. 资产身份不符、接触计量缺失、评估条件改变、GPU 或 API 上限超限时，立即停止。

### 观察与结论

- **观察**：尚无数据。
- **异常（运行前已知）**：GPU 物理复跑有随机性，由 A0′ 量化；门控组复用 A0 的运行，所以它们在不干预的交接上与 A0 完全相同，这是设计使然，不是巧合。
- **结论**：尚未运行。
