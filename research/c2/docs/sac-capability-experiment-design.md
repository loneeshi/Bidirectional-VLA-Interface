# C2 开发实验：SAC 站位敏感性与 GPT 候选选择

## 要回答的问题

在同一个 Pick 交接状态下，只改变 SAC 的起始底盘站位，官方严格 Pick 结果会不会改变？若多个交接状态存在成功的新站位，GPT 能否根据调用前信息选得比候选平均更好？成功→失败和失败→成功都计入站位敏感性；只有失败→成功才算站位带来的挽救收益。

本实验单位是 **Pick 调用前的冻结状态**，不是完整 episode。它不估计端到端任务成功率。Place、手臂准备动作、basic/trace/experience 反馈消融另做实验。

## 配置（评测参数）

| 项 | 固定规则 |
|---|---|
| 任务与样本 | 审计既有16集 Pick/Place 调用；按事前规则冻结最多8个空手、未终止、可重建的 Pick 交接，保留不合格原因；不看候选结果换样本 |
| 执行器 | 同一官方逐物体 SAC checkpoint、控制器、相机、policy state、RNG、官方任务状态和严格 Pick 判据；Pick 最多200步且不重置官方剩余时限 |
| 底盘候选 | C0 原站位；C1/C2 局部前/后各0.20 m；C3/C4 局部左/右各0.20 m；C5/C6 偏航±0.35 rad。相对 C0，每个候选只改一个量 |
| 干预方式 | 各分支从同一冻结初态和历史动作独立重建；仅写回规定的底盘量，其余机器人关节、物体和任务计数保持；C0 与候选都执行同一帧全零稳定动作 |
| 资源 | A0–A2 不用 GPT、不训练、不碰 GPU0、不租 RunPod；GPU1 用量和实验室未知费用按财务账本登记。A3 的付费请求另按授权上限登记 |

## 分阶段实验设计

### A0 冻结交接

逐调用核对旧16集的严格结果、持物、累计力、任务指针、手臂状态和超时原因。只纳入原历史 Pick 严格失败且初态与前置动作可重建的交接；在任何新候选 SAC 结果出现前保存选择顺序、排除原因、源文件和身份哈希。历史失败只用于选样，不代替新的 C0 对照。

### A1 原站位重复对照

每个冻结状态独立重建并运行**三次同处理 C0**。比较逐步 SAC 动作、状态、接触力和官方 Pick 结果；三次不能重现同一结果者标为 `snapshot_not_reproducible`，不进入配对 A2。C0 严格成功的状态照样进入 A2，以检测换站位后成功保持或丧失。有限几何搜索、抓取模板和逆运动学无解只作诊断，**不是 A1 门槛**。

### A2 固定候选 SAC 扫描与 Oracle

对通过 A1 的状态，依次尝试全部六个固定新候选。每次编辑后核对实际站位、任务指针、持物与力；稳定步骤造成明显漂移、任务失效或已有有效碰撞的候选记为 `infeasible`，保留在预定清单中且不调用 SAC。不要求事前证明目标抓取可达：这正是 SAC 扫描要测的能力。其余候选调用一次相同 SAC，记录官方严格 Pick 成功、时限、接触力、逐步轨迹和失败原因。基础设施错误单列，不算任务失败。

逐冻结状态报告 C0、每个候选、**候选平均**（已执行新候选的严格成功比例）和 **Oracle**（C0 与已执行新候选中的最好严格结果）。候选平均是结果表的精确平均，**不随机抽签、不增加实验设置**。分别数清失败→成功、成功→失败和成功→成功；Oracle 知道结果，不能当作可部署策略。

### A3 GPT 选择

仅当**至少两个不同冻结状态**各有一个成功的新候选，且完整 prompt、真实调用前输入样例、候选图像、schema、模型参数和请求预算均已在不看该批候选 SAC 结果时冻结，才对所有合格状态各调用 GPT 一次。GPT 只在几何/稳定合格的离散新候选中返回一个 `candidate_id`；输入可以包含当前双相机图像、具名状态、持物/工具前提及各候选 **SAC 前** 的图像和相对站位，不得包含候选 SAC 结果或成功标签。无效输出记 `model_protocol_failure`，不人工代选。

固定指令：

> 为当前物体的一次 Pick 选择一个 SAC 起始站位。只能从 `eligible_candidates` 返回一个 `candidate_id`。根据当前图像、机器人状态和各候选在 SAC 前的图像，选择最可能满足官方 Pick 条件的候选。不要输出连续坐标、其他技能或第二次尝试。你看不到候选 SAC 结果。只输出 JSON：`{"candidate_id":"C1","reason":"一句简短的可观察理由"}`。

用同一张 A2 结果表比较 GPT 所选候选与候选平均、Oracle 和 C0；不得为 GPT 再运行一套不同的 SAC。若上述两个状态或输入冻结门槛未满足，记录 A3 `not_run` 及原因，保留原门槛。

## 记录与解释边界

原始状态/RNG、源码/checkpoint/hash、C0 三次轨迹、每个候选的准入与 SAC 结果、GPT 完整输入输出以及实际资源用量均落盘。严格 Pick 与曾抓住物体、接近目标、整集成功分别报告。所有阶段性进展、异常和数值结果按 [`docs/log/TEMPLATE.md`](../../../docs/log/TEMPLATE.md) 的“问题—配置—结果—观察与结论—下一步”结构写入 result，不追加到本设计。
