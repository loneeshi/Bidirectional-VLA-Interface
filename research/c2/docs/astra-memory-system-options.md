## 与现有 H 条件的关系

| 已有条件 | 记忆形式 | 局限 |
|---|---|---|
| H0 | 无跨尝试记忆，只有本次尝试内的完整历史 | 对照组 |
| H1 | 同一交接此前各次尝试的原始历史，直接放进 prompt | 只对同一交接有效；上下文和费用随尝试次数线性增长 |
| H2 | H1 加其他开发交接上 SAC 成功的轨迹 | 示范是人工挑选的固定集合，不随 Astra 自己的经验增长 |

下文的方案都在回答同一个问题：**经验能不能跨交接积累，并且以比原始历史更紧凑的形式复用？**

## 候选方案

### M1 反思提炼记忆（Reflexion／RPent 式）

- 每次尝试结束后，由模型自己把轨迹、反馈和 hindsight 提炼成若干条文字教训，例如"深碗边缘深度噪声大，定位时取碗内侧点"。
- 教训存入跨交接的记忆库，新交接开始时按目标类别或场景检索若干条放进提示。
- 可以加一个整理步骤：合并重复教训，删去和后续结果矛盾的教训，并记下每条教训的来源尝试。
- 优点：实现最简单，和现有 `done`／`give_up` 的 hindsight 直接衔接。
- 风险：模型可能写出错误的教训并反复强化。每条教训必须能追溯到来源尝试和官方结局。

### M2 情景轨迹检索（ExpeL 式经验库）

- 存储每次尝试的关键帧、规划与实测末端轨迹、夹爪事件、官方结局和 hindsight。
- 新交接时按传感器可得的特征检索相似经验，例如目标语义类别、深度估计的目标高度、相机视角下的外观。
- 检索结果按 H2 的 video+action 格式编排，并声明"只作参考，不要盲目回放"。
- 与 H2 的区别：经验库包括 Astra 自己成功和失败的尝试，并且随运行增长。
- 风险：检索特征不能用场景真值计算，否则就是用真值做了筛选（见下文约束）。

### M3 Skill Pool（Voyager 式技能库）

- 把成功尝试里可复用的操作片段抽象成带参数的技能，例如"俯视抓取：在目标上方 h 处对准 → 下降 d → 闭合 → 抬起 → `return_to_rest`"。
- 技能以新工具或宏的形式交给模型，参数由模型根据当次观测填写。技能内部只调用现有的末端工具，执行时仍走同一个 IK 和官方动作接口。
- 技能入库前必须验证：在其他开发交接上至少复现一次严格成功，并且不含任何写死的场景坐标。
- 模型可以提议新技能或修改已有技能，每次修改都记录版本。
- 这是组会提到的"区别于 prompt 的学习形式"最直接的候选：学到的内容是可执行结构，不只是文字。
- 风险：技能参数可能悄悄编码某个场景的几何。入库审查要检查这一点。

### M4 机器人自身能力记忆（自标定）

- 记录与场景无关、只和机器人本体有关的经验，例如：不同躯干高度下手臂的可达范围、哪些末端姿态经常被 `check_path` 拒绝、`return_to_rest` 通常需要多少步。
- 这些信息来自机器人自身运动学和执行反馈，符合导师 2026-09-28 关于 IK 的裁定，可以在主条件中使用。
- 可以单独做，也可以作为 M1～M3 的公共底层。

### M5 参数层学习（不作为候选，只作记录）

- 对 Astra 做微调或偏好优化，属于 prompt 以外的学习，但闭源 API 模型不可行，换开源模型又会改变"模型是因素"这一前提。暂不考虑。

## 约束（所有方案共同适用）

以 `AGENTS.md` 中 "C2 GPT input policy" 为准：

- **写入记忆的内容只能来自主条件允许的信号**：机器人传感器 RGB-D、本体感知、工具反馈、模型自己的 note 和 hindsight，以及用户已确认合规的官方结局和终止类别。
- **评估端真值不能写入记忆**：`is_grasped`、接触物体身份、目标真值位姿、基于真值的失败归因都不能进入主条件记忆。如果要做"用真值归因写教训"的版本，只能作为特权消融并明确标注。
- **检索和筛选也不能用真值**：按真值目标位置或导航网格挑选相似经验，等同于用真值过滤候选。
- **泄题**：测试集交接自己的经验不得进入测试时的记忆。测试前冻结记忆库，测试集只评一次。
- **理由与归因**：每次工具调用仍须带 rationale；失败归因要检查记忆中的哪条内容影响了决策，并区分"记忆本身是错的"和"记忆是对的但执行偏离"。

## 评估要点（待写实验设计时细化）

- **基线**：必须和 H0 比，不能和"第 1 次尝试"比。普查中 20 个失败原样复跑有 4 个成功，重试本身就有随机收益。
- **指标**：达到严格 Pick 成功所需的尝试次数、前 K 次累计成功率、每次成功的 API 费用。
- **顺序效应**：跨交接积累的记忆受处理顺序影响。开发集至少跑两种固定顺序，或者先在开发集上建库、冻结后再评测试集。
- **对照**：同等 token 预算下，比较提炼记忆（M1～M3）和原始历史（H1／H2），以区分"信息更多"和"形式更好"两种解释。
- **记忆消融**：清空记忆库、打乱检索结果（给不相关的经验），检查收益是否确实来自相关经验。
