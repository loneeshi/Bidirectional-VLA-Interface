## 补充归因：闭合前逆模型控制振荡（2026-09-29 UTC）

针对用户“什么原因、是否能修复”，只读重算了这10步的冻结A1单步预测。模型输入是实测前一步位移与真正发出的动作，没有拟合新参数、修改控制器或执行新仿真。见[逐步残差](control-model-residuals.json)与[复现脚本](analyze_control_response.py)。

1. **腕弯出现满幅反向振荡**：最后6步指令交替+1/-1，实测每步约±0.0386rad。最后4步，A1只预测约±0.0034rad，真实响应约为其11倍。当前闭合前控制把该模型直接求逆，再用满增益位置反馈，形成反复过冲的表现。模型失配及振荡是实测事实；它们导致精调难以在10步内收敛，是有依据的控制归因。
2. **躯干刹停也未符合模型预测**：10步每一步的A1预测位移均约0，实测位移绝对值最大4.217mm，末步1.736mm。代码`_compensate`每步将躯干参考重置为实测高度，闭合前`delta=0`时没有相对固定高度的位置误差项，只剩逆模型动量抵消。因此没有独立的固定高度反馈去纠正模型误差。手臂同时在补偿这段运动。
3. **IK求解没有阻塞这10步**：10次均有解、未触发跳解；闭合命令尚未发出，不能把结果称为抓取物理失败。回休息位仍在7步内满足官方三项判据。

可以修正实现，但还不能保证在原2mm/0.02rad、躯干1mm与10步门内通过。优先方向是给闭合前稳定阶段独立的固定参考和带阻尼的实测反馈，限制反向动作幅度/变化，避免把粗略A1模型的精确逆当作刹停保证。腕弯控制需修；仅锁躯干不会消除已观察到的腕弯振荡。是否保留活动躯干仍需按用户规则确认。原参数/模型/阈值和失败记录保留，任何实现修订应另建版本并重新验证，不能把阈值放宽当作修复。对A1失配的更底层动力学原因，单条轨迹不足以作唯一归因。

本补充仅新增CPU分析：GPU/API/仿真0，未重新启动任何进程。
