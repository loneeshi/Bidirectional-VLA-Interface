# r3离线跟进：躯干参考与末端可解性不一致

所在阶段：C2视觉试点失败归因/CPU修复。推进：两段卡点从归档实测状态重建，发现固定躯干参考下IK7失败，而同末端点IK8通过。阻塞：尚未实现/验证新的末端调度器；历史SSL错误缺少具体reason不可追溯判定。下一门：独立控制器修订设计与CPU验证；无物理/API启动。

## 5号可复现证据

重建使用冻结URDF/响应参数和物理轨迹，调用原v6规划/调度与PreferredIK。环境step回调强制报错，未运行仿真。两次重建的卡点参考高度与原日志差分别8.44e-10m、0。

|指令turn|卡点/总参考点|计划躯干m|末端实测躯干m|计划躯干IK7位置残差|实测躯干IK7位置残差|IK8选躯干m|IK8位置残差|
|---|---|---|---|---|---|---|---|
|5|26/35|0.064137|0.064871|11.374mm|10.772mm|0.102495|0.604mm|
|7|9/17|0.023582|0.023895|5.670mm|5.421mm|0.063799|0.164mm|

两IK8解均通过原姿态/连续性门；IK7容差仍2mm/0.02rad，没有放宽。这里的IK7失败是冻结数值求解器未找到解，不是全局不可达数学证明。CPU重新求解以上一次实测关节为种子，与在线缓存种子略不同；高度/路径重建吻合，但不声称逐次求解完全重放。

原物理日志78次IK失败全为ik_not_found，无jump_rejected；两指令等待26/52步。末段躯干高度已接近参考，在此高度继续等待也未恢复。这支持归因为执行参考耦合缺陷，而不是单纯躯干滞后。

v6先生成末端笛卡尔插值，再按段起终躯干生成独立梯形高度；共同cursor只对齐时间，没有验证每个高度与末端点组合的可解性。v7在IK7失败时冻结cursor并重复该高度；若该组合本身不被IK7接受，推进会卡住。静态check_path验证的是IK8路径，未覆盖这一重采样后的组合。因此check_path通过不能推出动态执行完成。

建议新版本让躯干轨迹以逐点IK8可行路径为基础做时间参数化，重新采样后逐点校验IK7，运行时再按实测高度补偿。不得以放宽容差、增加步数、场景碰撞过滤或锁定躯干代替修复。现阶段只是修订建议，未改动v13或物理验证。

## SSL修补

r3只留SSLError(errno1)，没有library/reason，不能补造具体根因。新增诊断保存SSL库/符号reason及证书错误布尔值，不保存自由文本/认证头。bounded-transport-v2仅增加明确的SSLEOFError、SSLZeroReturnError及UNEXPECTED_EOF_WHILE_READING重试；证书验证失败、未知通用SSLError仍停止。次数和费用门不变，USD阈值仍来自授权配置。不能声称该修改必定修复r3未知SSL错误。

完整eef回归483 passed in9.34s，专项23项通过。新版本尚未打包或实测；旧包/账本/分母不改。模型API0/GPU0/仿真0；无新增Pick成功。证据和源码哈希见receipt.json及ik-reconstruction.json。
