# Astra Pick

MS-HAB 的 Pick 任务（Fetch 移动机械臂）上，由语言模型决策、系统执行的工具闭环。模型只看机器人自己的传感器，每一轮给出一个工具调用；系统执行，并把实测结果交回模型。

**这份代码用于阅读和复核方法，不能独立运行。** 本仓库包含决策循环、机器人侧执行代码和实验用到的底层控制器，但不包含 MS-HAB／ManiSkill 环境、4096×4096 包装纹理资产、模型 API 账号和实验室服务器配置。

## 一轮决策

```
机器人头/手 RGB-D、关节、相对里程计
        │
        ▼
  模型：一个工具调用 + 简短依据（note）
        │
        ▼
  系统：检查 → 执行 → 记录实测结果
        │
        ▼
  反馈：实际到位情况、残差、退出原因、剩余预算
        │
        └──────────► 下一轮
```

模型决定看哪里、到哪里、用什么姿态抓；系统负责执行、安全停止和记账。官方评分只在评估侧使用。

## 信息边界

| 进入模型 | 不进入模型 |
|---|---|
| 机器人头／手 RGB-D、关节、相对里程计 | 物体世界位姿、场景网格、可行区域图 |
| 目标的外观描述（颜色、形状、文字，不含位置） | 官方抓持标志、接触体身份、官方最终评分 |
| 机器人自身运动学（FK／IK）的结果 | 第三人称相机、由真值筛选的候选位置 |
| 实测执行反馈、预算余量 | 评估侧坐标 |

## 文件

| 文件 | 作用 |
|---|---|
| `pick.py` | 决策循环：配置（profile）、请求构造、工具参数校验、反馈整理 |
| `run_case.py` | 单例运行与监督：环境接线、预算记账、归档与回放检查 |
| `memory.py` | 单例内的有限证据存储，只保存带来源和时效的观测 |
| `profiles.json`、`prompt.md` | 各配置使用的提示和冻结数据 |
| `robot/eef_tools.py` | 仅依赖机器人的 IK 与位姿工具 |
| `robot/executor.py`、`robot/motion.py`、`robot/arm.py` | 动作执行、到位判定、受阻和失持出口 |
| `robot/clearance.py` | 只用机器人 RGB-D 的间隙报告；只报告，不否决动作 |
| `robot/sensing.py`、`robot/dynamics.py` | 传感读取与控制参数 |

`controller/` 是实验加载的底层控制器：`full-stack/fetch_*.py` 为运行时、回合、跟踪和驱动，`full-stack/upstream/flowsde_ctrl/` 为整身末端跟踪控制器库，`preflight.py`、`task_rules.py` 为启动前检查和任务规则；`scripts/` 为快照导出与恢复核对。`run_case.py` 按 `controller/full-stack` 的目录布局把它们加入模块搜索路径。

`research/astra_pick/src/bvi/pick_system/` 是 `run_case.py` 用到的最小依赖：跨进程快照工具及其诊断。

## 配置

每个实验条件是一个 profile，由默认关闭的开关组合而成，旧配置的请求字节保持不变。当前基线是 `Sol-pick-v3-lean-s1.3`（已冻结）。`Sol-pick-v3-s2*` 是计划—执行接口，已完成 CPU 验证，尚无原生结果。

## 结果与边界

近距离 10 个开发案例（000–009）上，各配置的严格成功数为 5–7／10，每例一次。开发集已用于调参，不能当作泛化结果。逐批结论、失败归因和录像见[实验日志](../../docs/log/README.md)和[演示](../../docs/media/README.md)。

## 代码约定

- 评估侧真值、接触和世界位姿只用于评分和事后分析，不写回模型输入。
- 实验室路径通过环境变量 `BVI_LAB_ROOT` 指定，默认 `~/bvi-research`。
- API 密钥运行时从本地文件读取，不在代码或日志中保存。
